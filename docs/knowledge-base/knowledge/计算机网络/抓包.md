# 抓包方式

今天看到抓包突然有点好奇，在2026年的今天都有哪些抓包方式呢？以下根据层数从低到高来进行说明。

## 一、链路层抓包（最底层，什么都能抓）

这是最经典的方式——把网卡设为**混杂模式（Promiscuous Mode）**，让网卡把所有流经的数据帧都交给 CPU，而不是只收「发给自己的」。
### 1. 工具类
| 工具                     | 定位                                             |
| ---------------------- | ---------------------------------------------- |
| **tcpdump**            | Linux 命令行经典，BPF 过滤语法，一切自动化脚本的基础                |
| **Wireshark / TShark** | 图形界面 + 命令行，协议解析最全，事实上的行业标准                     |
| **netsh trace**        | Windows 自带，不装任何东西就能抓，适合应急                      |
| **pktmon**             | Windows 10/11 自带，微软新一代抓包，支持实时过滤、丢包分析、pcapng 导出 |
| **dumpcap**            | Wireshark 套件里专用的抓包引擎，资源占用比 Wireshark 小         |
### 2. 抓包库（供开发者调用）
| 库                | 特点                                                         |
| ---------------- | ---------------------------------------------------------- |
| **libpcap**      | Unix/Linux 标配，tcpdump 和 Wireshark 都基于它                     |
| **WinPcap**      | Windows 上的老牌，已停止更新                                         |
| **Npcap**        | WinPcap 的继任者，支持 Windows 10/11 回环抓包、WLAN 原始帧，兼容 WinPcap API |
| **PF_RING**      | ntop 开发的零拷贝高速抓包框架，线速 10Gbps+                               |
| **AF_XDP / XDP** | Linux 内核 eBPF 路径，数据包在到达协议栈之前就能被捕获，性能极高                     |
| **DPDK**         | 绕过内核，直接从网卡 DMA 到用户态，适合 40G/100G 线速抓包                       |
| **AF_PACKET**    | Linux 原始套接字，比 libpcap 更底层                                  |

## 二、中间人方式（MITM，干涉通信来抓包）

当报文不经过你的网卡（比如跨交换机、两台别人设备间的流量），你需要「站到中间」。

### 1. ARP 欺骗

- 向目标持续发送伪造的 ARP 应答，把流量引向你的机器
- 工具：**Ettercap**、**bettercap**、**arpspoof**
- 经典但容易被 ARP 防火墙 / 动态检测发现

### 2. DHCP 欺骗 / 恶意 DHCP

- 伪造 DHCP 服务器，把自己的 IP 设成客户端的默认网关
- 工具：**Yersinia**、**responder**的一部分功能

### 3. ICMP 重定向

- 伪造 ICMP Redirect 报文，告诉目标「有更好的路由」，把流量引过来
- 现代操作系统大多默认忽略，但在老网络设备上还能奏效

### 4. 交换机端口镜像（SPAN / RSPAN / ERSPAN）

- **这是企业网络抓包的正道**：在交换机上配置端口镜像，把指定端口或 VLAN 的流量复制一份发到你的抓包端口
- 支持远程镜像（RSPAN）和跨三层镜像（ERSPAN），Cisco / Juniper / Arista / H3C 都支持

### 5. 网络分光器（TAP）

- 硬件设备，串联在链路中间，复制光/电信号
- 100% 实时、无丢包、不可检测（被动光学器件）
- 分 **网络分光器** 和 **汇聚/再生 TAP**

### 6. SSL/TLS 中间人代理（应用层抓明文）

- 在客户端和服务器之间架代理，用自签 CA 证书重签所有 HTTPS 流量
- 工具：**mitmproxy**、**Burp Suite**、**Charles**、**Fiddler**
- 前提条件：必须在客户端设备上安装你的 CA 根证书


## 三、应用层 / 代理抓包

不碰链路，直接在应用层截取。

|工具|特点|
|---|---|
|**mitmproxy**|开源 CLI/Web 界面，支持 Python 脚本插件，自动化解包神器|
|**Burp Suite**|Web 渗透测试标配，拦截→修改→放行，Repeater/Intruder 等|
|**Charles**|跨平台，移动端抓包友好，图形化 Map Local/Map Remote|
|**Fiddler**|Windows 经典，脚本能力强大（FiddlerScript），HTTPS 解密|
|**Proxyman**|macOS 原生，UI 精美，原生支持 Apple Silicon，iOS/Android 远程抓取|
|**HTTP Toolkit**|一键式拦截，自带教程，适合教学和快速调试|
|**Wireshark + SSLKEYLOGFILE**|浏览器环境变量导出 TLS 会话密钥，事后在 Wireshark 中解密——不是代理，但效果类似|
|**eBPF + Go 应用内 Hook**|比如 Pixie、Cilium 的 Tetragon，在 K8s Pod 内直接捕获，不注入 sidecar|

## 四、无线抓包（Wi-Fi / 蓝牙 / Zigbee）

### Wi-Fi

- **监听模式（Monitor Mode）**：需要网卡芯片支持（如 MT7612U、RT5572、AR9271、AX200 部分驱动）
- 工具：**airodump-ng**（Aircrack-ng 套件）、**Kismet**、**Wireshark（开启监控模式）**、**hcxdumptool**
- 带 WPA3 的 PMF 保护帧抓包难度上升，但仍可抓到握手阶段的 EAPOL 帧

### 蓝牙

- **Ubertooth One**：经典蓝牙抓包硬件
- **nRF52840 / Adafruit Bluefruit LE Sniffer**：BLE 抓包，配合 Wireshark 插件
- **TI CC2540**：经典的 BLE USB Dongle 嗅探器

### Zigbee / Thread / Z-Wave（IoT 协议）

- **Zigbee2MQTT 调试模式** + CC2531 USB Dongle
- 专用工具：**Perytons Protocol Analyzer**、恩智浦的 **K32W** sniffing


## 五、云端 & 容器环境

### AWS

- **VPC Traffic Mirroring**：相当于云端的 SPAN，可以把 EC2 的 ENI 流量镜像到另一个实例或 Gateway Load Balancer
- **VPC Flow Logs**：不是全包抓取，是元数据级别的流日志

### Azure

- **Network Watcher → Packet Capture**：Azure 原生包捕获，可按 VM/网卡/Nsg 做

### GCP

- **Packet Mirroring**：与 AWS VPC Traffic Mirroring 对标

### Kubernetes

- **kubeshark**（原 Mizu）：通过 eBPF 无侵入抓取 Pod 流量
- **Istio / Linkerd** 的 sidecar 也可以输出流量日志，但不是全包捕获
- **tcpdump in Ephemeral Container**：K8s 1.23+ 支持用 debug 容器直接进 Pod 的网络命名空间跑 tcpdump


## 六、物理层 / 硬件抓包（最硬核）

|方式|说明|
|---|---|
|**逻辑分析仪 + 总线探针**|抓 SPI / I²C / UART / CAN 总线数据，IoT 硬件调试|
|**USB 协议分析仪**|如 Beagle USB 480、Total Phase，抓 USB 通信|
|**SDR（软件定义无线电）**|RTL-SDR / HackRF / BladeRF 抓射频信号，分析特定频段协议|
|**HDMI 捕获卡**|虽然不算网络包，但确实是数据包（TMDS）抓取|
|**高速抓包卡**|Endace、Napatech 等专用 FPGA 网卡，纳秒级时间戳，金融交易场景用|

## 七、各大平台的总结速查

|场景|首选方式|
|---|---|
|本地调试 HTTP/HTTPS|mitmproxy / Burp Suite / Proxyman|
|局域网内全量抓包|Wireshark + 交换机 SPAN|
|Windows 快速应急|`pktmon start --capture` 一条命令|
|Linux CLI 抓包|`tcpdump -i eth0 -w capture.pcap`|
|移动端 App|电脑开代理 + 手机设代理 + 装 CA 证书|
|Wi-Fi 密码破解相关|airodump-ng + 支持监听模式的网卡|
|K8s 生产环境|kubeshark 或 Ephemeral Container + tcpdump|
|云上 AWS|VPC Traffic Mirroring|
|10Gbps+ 高速不掉包|PF_RING / DPDK / Napatech 抓包卡|
