RIP（Routing Information Protocol，路由信息协议）是一种**基于距离矢量的内部网关协议(IGP)**，也就是根据**跳数**来度量路由开销，进行路由选择。
和其他的路由协议相比（比如[OSPF](/knowledge-base/knowledge/计算机网络/OSPF.md)，[ISIS](/knowledge-base/knowledge/计算机网络/ISIS.md)等），RIP协议实现更简单，对带宽，配置和管理要求也更低，但是受到**路由跳数**和**收敛速度**限制，大于15跳就认为网络不可达，所以没办法用在大型网络中。不过由于配置和维护管理比较简单，所以也许仍有应用。

## 为什么使用RIP？

在动态路由出现之前，[静态路由](/knowledge-base/knowledge/计算机网络/静态路由.md)有几个问题无法解决：
- 当网络拓扑结构和链路状发生变化，需要对[路由器](/knowledge-base/knowledge/关于物理设备/路由器.md)的静态路由信息**进行大范围修改，工作复杂度高**
- 网络发生故障时，**不能重选路由**，很可能使路由失败

所以动态路由协议就出现了：路由器**自动学习**，自适应网络的变化，**无需人工更改配置**。

## RIP特点

- RIP有三大版本：**RIPv1（RFC 1058）、RIPv2（RFC 2453）和RIPng（用于IPv6，RFC 2080）**
- **传输层协议**：基于UDP协议，使用端口号520进行通信
- **更新方式**：默认每30秒周期性发送完整路由表更新，拓扑变化时可触发更新
- **协议优先级（华为VRP）**：RIP默认优先级为100（数值越小越优先），低于直连路由（0）和静态路由（60）；思科IOS中RIP默认管理距离为120
- **收敛特性**：属于"慢收敛"协议，适用于对收敛速度要求不高的中小型网络

## 工作原理

### 1. 距离矢量算法

每台路由器只与直连的RIP邻居交换完整路由表。路由器不了解全网拓扑，仅知道"去往目标网络的方向+距离"，RIP的路由表项包含以下信息：目的地址、下一跳地址、出接口、度量值、路由时间和路由标记（Route Tag）

### 2. RIP运行过程

- 路由器启动RIP后，向相邻路由器发送Request请求报文，相邻路由器回应携带本地路由表的Response报文
    
- 收到响应后，路由器更新本地路由表，并向邻居发送触发更新报文。各路由器周期性向邻居发送路由表，同时利用老化机制对超时路由进行处理
    
- 路由器将从邻居学到的路由条目度量值加1后写入本地路由表，通过逐跳传递最终全网收敛

### 3. 度量值与选路原则

- **度量值**：以跳数（Hop Count）作为唯一度量标准，最大有效跳数为15，16跳视为不可达
 ^eb198c
- 路由器到直连网络的跳数为0，通过一个路由器可达的网络的跳数为1，依此类推
    
- 当存在去往同一目的地的多条路由时，RIP仅比较跳数（度量值），跳数最小的路由被选为最优路由。此外路由器采用等价负载分担（ECMP），默认最多支持4条等价路径（华为VRP中最多可配置16条）
    
- RIP不会考虑链路带宽、延迟、负载等实际因素，这也是其选路不够精细的局限之一

## 四大核心定时器

计时器是RIP稳定运行的核心，不同厂商默认值略有差异

|计时器名称|华为VRP默认值|思科IOS默认值|核心作用|
|---|---|---|---|
|更新计时器（Update）|30秒|30秒|周期性发送路由更新报文；实际发送时加入±5秒随机偏移量|
|老化/无效计时器（Invalid）|180秒|180秒|若超时未收到关于某路由的更新，将该路由度量值置为16（不可达）|
|抑制计时器（Suppress）|0秒（默认关闭）|180秒|路由度量值变大时进入抑制状态，防止路由抖动|
|垃圾收集计时器（Garbage-Collect）|120秒|120秒|路由被标记为不可达后保持120秒，超时仍无有效更新则彻底删除|
一条路由从失效到彻底删除，最长需要180+120=300秒（约5分钟）。华为默认关闭抑制计时器，目的是加快收敛速度


## 防环机制

距离矢量协议天然存在路由环路风险，那么RIP是如何避免的？

### 1.计数到无穷

将[度量值](/knowledge-base/knowledge/计算机网络/RIP.md#^eb198c)等于16的路由定义为不可达，路由环路发生时，某条路由度量值不断增加直到16，该路由即被视为不可达

### 2. 水平分割

RIP从某个接口学到的路由，不会再从该接口发回给邻居路由器。这不但减少带宽消耗，还能防止路由环路

### 3. 毒性逆转

RIP从某个接口学到路由后，将该路由的度量值设置为16（不可达），并从原接口发回邻居路由器，清除对方路由表中的无用信息

> **注意**：水平分割和毒性逆转互为替代机制。华为/思科设备默认仅开启水平分割；若同时开启两者，毒性逆转生效

### 4. 触发更新

一旦某条路由的度量值发生变化，立刻向邻居发布更新报文，不等更新周期到来，从而加速网络收敛

### 5. 抑制计时器

当收到路由度量值变大的更新时，路由器在一定时间内忽略更差或不可达的路由，等待网络稳定，避免错误信息在网络中泛洪

### 6. 路由毒化

当检测到直连网络不可达时，主动将该路由的度量值设为16（即"下毒"）并向邻居通告，加速全网同步该路由的失效状态

## RIPv1 vs RIPv2

生产环境中建议使用RIPv2

| 对比维度        | RIPv1               | RIPv2                      |
| ----------- | ------------------- | -------------------------- |
| 路由类型        | 有类路由协议（Classful）    | 无类路由协议（Classless）          |
| VLSM / CIDR | 不支持                 | 支持，路由条目携带精确子网掩码            |
| 更新方式        | 广播（255.255.255.255） | 组播（224.0.0.9，默认），也可配置为广播   |
| 路由认证        | 不支持                 | 支持明文/MD5/HMAC-SHA256认证     |
| 路由汇总        | 仅支持主类自动汇总，不可关闭      | 默认开启自动汇总，可手动关闭；支持接口级手动精确汇总 |
| 下一跳优化       | 不支持                 | 支持携带最优下一跳地址                |
| 路由标记（Tag）   | 不支持                 | 支持，可用于路由策略过滤和控制            |
| 最大路由条目      | 每报文最多25条            | 无认证时25条，有认证时24条            |
| 报文兼容性       | 只接收RIPv1报文          | 可接收RIPv1和RIPv2报文，向下兼容      |
