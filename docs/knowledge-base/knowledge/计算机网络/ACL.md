访问控制列表ACL（Access Control List）是由一条或多条 `permit/deny` 规则组成的**报文过滤器**，通过匹配报文的特征（地址、端口等）来识别流量，进而决定允许或拒绝。

## 匹配机制

遵循 **“一旦命中即停止匹配”** 的原则。设备从编号最小的规则开始依次检查，一旦报文匹配某条规则，就执行该规则的动作并停止继续往下查。因此，**越精确的规则编号应该越小、越靠前**，避免被前面的宽松规则“误拦”或“误放”。

## ACL分类

- **基本 ACL (2000-2999)**：只能根据**源IP地址**来过滤。适用于简单场景，比如只允许某个网段访问。
    
- **高级 ACL (3000-3999)**：可以基于**五元组**（源IP、目的IP、协议类型、源端口、目的端口）做精细过滤。这是最常用的一类，能精确控制到具体的应用。
    
- **二层 ACL (4000-4999)**：根据**MAC地址**、VLAN ID等二层信息过滤。常用于防范ARP欺骗、控制非IP报文。
    
- **用户 ACL (6000-6031)**：同样支持五元组过滤，但与高级ACL面向的场景和调用方式不同，主要用于用户接入管理。

## ACL步长

步长，是指系统自动为ACL规则分配编号时，每个相邻规则编号之间的差值。
系统为ACL中首条未手工指定编号的规则分配编号时，使用步长值作为该规则的起始编号；为后续规则分配编号时，则使用大于当前ACL内最大规则编号且是步长整数倍的最小整数作为规则编号。
举个例子：ACL中包含规则rule 5和rule 12，ACL（特指基本ACL、高级ACL、二层ACL、用户ACL）的缺省步长为5，大于12且是5的倍数的最小整数是15，所以系统分配给新配置的规则的编号为15。
`step 2` 表示将步长设置为2。

## ACL 匹配顺序

首先：**permit规则与deny规则是相互矛盾的**。deny：拒绝通过；permit：允许通过。
华为设备支持两种ACL匹配顺序：配置顺序（**config**模式）和自动排序（**auto**模式）。缺省的ACL匹配顺序是**config**模式。

### 配置顺序

系统按照ACL规则编号从小到大的顺序进行报文匹配，规则编号越小越容易被匹配。
- 如果配置规则时指定了规则编号，则规则编号越小，规则插入位置越靠前，该规则越先被匹配。
- 如果配置规则时未指定规则编号，则由系统自动为其分配一个编号。该编号是一个大于当前ACL内最大规则编号且是步长整数倍的最小整数，因此该规则会被最后匹配。

### 自动排序

是指系统使用“[ 深度优先](/knowledge-base/knowledge/计算机网络/ACL.md#表1-2%20“深度优先”匹配原则)”的原则，将规则按照精确度从高到低进行排序，并按照精确度从高到低的顺序进行报文匹配。规则中定义的匹配项限制越严格，规则的精确度就越高，即优先级越高，系统越先匹配。

## ACL生效时间段

还是举个例子吧：某公司要求，在上班时间只允许员工浏览与工作相关的几个网站，下班或周末时间才可以访问其他互联网网站；再如，在每天20:00～22:00的网络流量的高峰期，为防止P2P、下载类业务占用大量带宽对其他数据业务的正常使用造成影响，需要对P2P、下载类业务的带宽进行限制。

## 补充

1. **跨厂商差异 (Cisco)**：Cisco 的命名逻辑不同。它的 **标准ACL (编号1-99)** 对应华为的基本ACL，只查源IP；**扩展ACL (编号100-199)** 对应华为的高级ACL，可查五元组。在多厂商网络排错时需要注意这个对应关系。
    
2. **特殊 ACL 类型**：
    
    - **动态 ACL (Lock-and-Key)**：采用“先认证、后授权”的模式。用户需要先通过 Telnet 登录设备进行身份验证，通过后，设备会动态生成一条临时的 `permit` 规则，让该用户的IP可以访问目标资源。适用于临时访问需求的场景。
        
    - **反射 ACL (Reflexive ACL)**：能实现真正的单向防火墙。它允许内部主动发起的会话，并动态创建一条临时的返回通道，只放行该会话的应答流量，严格拒绝外部主动发起的连接。这比仅仅依赖检查TCP报文的ACK标志位更安全可靠。
        
3. **应用延伸**：ACL 的价值不止于“过滤”，它还被作为一种 **“流量分类器”** 广泛用于：
    
    - **策略路由 (PBR)**：用 ACL 挑出特定流量（如视频会议），不查普通路由表，而是强制走一条更优的专线。
        
    - **网络地址转换 (NAT)**：用 ACL 定义哪些内部IP才被允许进行地址转换上网。
        
    - **服务质量 (QoS)**：用 ACL 识别VIP业务流量，为其标记高优先级，保障关键应用。
        
4. **局限性**：
    
    - **无状态**：传统 ACL 只孤立地检查每个报文，不追踪连接状态。例如，放行了请求方向，它会机械地认为返回方向的流量是独立的，需要另一条规则处理。这与能自动识别“会话”的状态化防火墙有本质区别。
        
    - **资源消耗**：在核心设备上配置大量复杂ACL规则，会消耗硬件 `TCAM`（一种高速查找的硬件资源）空间，极端情况下可能导致性能下降或无法新增规则。
        

## 表1-2 “深度优先”匹配原则

| ACL类型      | 匹配原则                                                                                                                                                                                                                                                                                                      |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 基本ACL&ACL6 | 1. 先看规则中是否带VPN实例，带VPN实例的规则优先。<br>2. 再比较源IP地址范围，源IP地址范围小（IP地址通配符掩码中“0”位的数量多）的规则优先。<br>3. 如果源IP地址范围相同，则规则编号小的优先。                                                                                                                                                                                            |
| 高级ACL&ACL6 | 1. 先看规则中是否带VPN实例，带VPN实例的规则优先。<br>2. 再比较协议范围，指定了IP协议承载的协议类型的规则优先。<br>3. 如果协议范围相同，则比较源IP地址范围，源IP地址范围小（IP地址通配符掩码中“0”位的数量多）的规则优先。<br>4. 如果协议范围、源IP地址范围相同，则比较目的IP地址范围，目的IP地址范围小（IP地址通配符掩码中“0”位的数量多）的规则优先。<br>5. 如果协议范围、源IP地址范围、目的IP地址范围相同，则比较四层端口号（TCP/UDP端口号）范围，四层端口号范围小的规则优先。<br>6. 如果上述范围都相同，则规则编号小的优先。     |
| 二层ACL      | 1. 先比较二层协议类型通配符掩码，通配符掩码大（协议类型通配符掩码中“1”位的数量多）的规则优先。<br>2. 如果二层协议类型通配符掩码相同，则比较源MAC地址范围，源MAC地址范围小（MAC地址通配符掩码中“1”位的数量多）的规则优先。<br>3. 如果源MAC地址范围相同，则比较目的MAC地址范围，目的MAC地址范围小（MAC地址通配符掩码中“1”位的数量多）的规则优先。<br>4. 如果源MAC地址范围、目的MAC地址范围相同，则规则编号小的优先。                                                                   |
| 用户ACL      | 1. 先比较协议范围，指定了IP协议承载的协议类型的规则优先。<br>2. 如果协议范围相同，则比较源IP地址范围。如果规则的源IP地址均为IP网段，则源IP地址范围小（IP地址通配符掩码中“0”位的数量多）的规则优先。<br>3. 如果协议范围、源IP地址范围相同，则比较目的IP地址范围。如果规则的目的IP地址均为IP网段，则目的IP地址范围小（IP地址通配符掩码中“0”位的数量多）的规则优先。<br>4. 如果协议范围、源IP地址范围、目的IP地址范围相同，则比较四层端口号（TCP/UDP端口号）范围，四层端口号范围小的规则优先。<br>5. 如果上述范围都相同，则规则编号小的优先。 |
