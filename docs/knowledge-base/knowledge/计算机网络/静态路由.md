# 静态路由

管理员**手工**写死的路由：去某网段，下一跳是谁、出哪块接口。路由器自己不会因为链路断了再去学一条新路。

```
ip route-static 192.168.2.0 255.255.255.0 10.1.1.2
```

<!-- more -->

优点是可控、不占带宽、排障时「这条路就是我写的」。缺点在 [RIP](RIP.md) 里已经碰到过：

- 拓扑一变，要大范围改配置
- 故障时**不会重选**，容易黑洞

所以稍大的网会改用动态 [IGP协议](IGP协议.md)（[RIP](RIP.md) / [OSPF](OSPF.md) / [ISIS](ISIS.md)）。静态并没有过时，常见还在用的场景：

- **缺省路由** `0.0.0.0/0`：出口、上云、末梢设备「其余都扔给上级」
- **桩网络**：只有一条路上行，学动态路由没意义
- **浮动静态**：写一条优先级更差的备份下一跳，主路挂了才接上

华为上静态默认优先级 60，比 RIP（100）更优，比 OSPF（10）更差。同一前缀多条时，先比优先级，再比度量。
