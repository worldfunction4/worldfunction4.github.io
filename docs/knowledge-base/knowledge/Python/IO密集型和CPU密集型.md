## 性能瓶颈（Bottleneck）
## 1. CPU密集型

定义：程序的运行速度主要是受限于**CPU的处理能力**
这类任务的大部分时间都在进行复杂的数值计算，逻辑推理或数据处理，CPU占用率通常会长时间保持在100%

### 典型场景
- **科学计算**：比如矩阵运算，求圆周率，大规模统计分析
- **多媒体处理**：视频转码，高清图片实时渲染
- **安全加密**：大量数据的哈希计算（比如比特币挖掘），RSA加密
- **压缩算法**：对海量文件进行高比例压缩
### 硬件表现
- **CPU**：满载，风扇狂转
- **内存/磁盘/网络**：通常是处于低负载或等待状态
## 2. I/O密集型
**核心定义**：程序的运行速度主要受限于**输入/输出（I/O）速度**
这类任务大部分时间都在等待——等磁盘任务完成，等网络数据包返回，等数据库查询结果。CPU在这类任务中大部分时间都在“休眠”或者等待信号。

### 典型场景
- **网络自动化**：通过SSH同时连接100太=台交换机
- **Web爬虫**：请求大量的URL并等待服务器响应
- **数据库操作**：从海量信息中检索信息
- **文件处理**：在硬盘中读写大量零碎的小文件
### 硬件表现
- **CPU**：占用率极低，通常不到5%
- **网络/磁盘**：带宽可能跑满，或者处于频繁的请求等待周期
## 3.深度对比：维度分析

|**维度**|**CPU 密集型 (CPU-bound)**|**I/O 密集型 (I/O-bound)**|
|---|---|---|
|**主要矛盾**|计算速度不够快|等待时间太长|
|**瓶颈所在**|CPU 核心主频与核心数|磁盘带宽、网络延迟、内存带宽|
|**CPU 状态**|极度繁忙|大量闲置 (Idle)|
|**单任务耗时**|取决于算法复杂度|取决于外部设备响应速度|
|**优化方向**|**多进程**、更高效的算法、GPU 加速|**多线程**、**异步协程 (Asyncio)**、缓存|
## 4. 为什么这个区别在Python中极其重要？

在 Python 环境下，因为[GIL（全局解释器锁）](/knowledge-base/knowledge/专业术语/GIL（全局解释器锁）.md)的存在，所以这个区别十分关键：
**对于CPU密集型任务**：
	如果使用**多线程**，Python 会因为GIL的限制，让多个线程轮流在一个CPU核心上执行，反而会因为频繁切换上下文（context switch）导致运行更慢。
		**正确使用方法**：使用 `multiprocessing`(多进程)，利用多核CPU的物理优势实现真正的并行
**对于I/O密集型任务**：
	如果使用**多进程**，虽然能够解决问题，但会消耗大量的内存资源（每个进程都是独立的）。
		**正确使用方法**：使用`threading`(多线程)或`asyncio`(协程)。因为CPU在等待I/O时是空闲的，此时切换到另一个线程去发起新的请求，能极大提高整体效率。
## 5. 混合型任务：真实复杂场景

在实际的开发中，任务其实并非纯粹
比如：**备份100台交换机的配置并对其进行文本分析**。
	1.**连接并获取配置**：这是 **I/O 密集型**（等网络返回数据）。
	2.**对配置进行复杂的正则匹配和逻辑校验**：这是 **CPU 密集型**。
**进阶策略**：
- 使用 `ThreadPoolExecutor` 负责并发抓取数据（解决 I/O 等待）。
- 抓取到的数据丢进一个队列，由 `ProcessPoolExecutor` 负责解析（解决计算瓶颈）。
## 总结

也就是说使用多线程还是多进程只需要从以下几个方向考虑即可：
- **CPU占用率**：如果代码跑起来电脑风扇不转，CPU也就几个点，那么说明大概率是**I/O密集型**，当然如果电脑发烫，CPU占用率变高，那说明大概率是**CPU密集型**
- **工具的选择**：CPU密集的话，使用多进程；I/O密集的话，使用多线程/协程
