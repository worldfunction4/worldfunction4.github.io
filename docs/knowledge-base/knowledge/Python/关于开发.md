# 有机生长式开发（Organic Growth Development）

## 核心原则

硬编码跑通 → 感受痛点 → 只加一层解决痛点 → 循环

每次只问："现在有什么不舒服的？"
永远不在痛点出现之前加抽象。

## 四种开发方式对比

### 1. 瀑布式（Waterfall）
需求 → 设计 → 开发 → 测试 → 部署
- 优势：结构清晰，文档齐全
- 劣势：需求写死后很难调头
- 适合个人：❌ 不适用

### 2. 敏捷式（Agile / Scrum）
两周一迭代，每次交付可用的东西
- 优势：适应变化快
- 劣势：需要纪律和固定的节奏
- 适合个人：协作时需要

### 3. 瀑布开头敏捷中间
架构预先设计，细节迭代开发
- 优势：大方向稳，小步灵活
- 劣势：需要足够的经验做对架构决策
- 适合个人：老手建长期项目时

### 4. 有机生长式（Organic Growth）
从硬编码开始，感知痛点后才加抽象层
典型路径：硬编码 → YAML → Excel → 多设备 → 异常处理 → 报告 → 云

- 优势：每一层抽象都有"为什么"的故事，不会过度设计
- 劣势：代码一开始脏，重构压力累积
- 适合个人：学习新技术、从零建项目、赶 demo

## 个人场景选择

| 场景 | 推荐方式 | 原则 |
|------|---------|------|
| 学新技术 | 有机生长 | 先跑通再感受痛 |
| 赶 demo/面试 | 有机生长+观众视角 | 每层回答一个简历亮点 |
| 维护老项目 | 小步重构 | 每次提交只改一个东西 |
| 跟人合作 | 敏捷 | 对方需要承诺的时间线 |

## 关键认知

抽象是债务，不是资产——默认不该欠，真不舒服了才借。

代码不是设计出来的，是从具体经验里"长"出来的。
