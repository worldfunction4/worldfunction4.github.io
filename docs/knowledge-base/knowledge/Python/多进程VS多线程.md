## 核心概念

### 进程 Process

操作系统 资源分配 的最小单位。就像独立的工厂，相互隔离，拥有独立内存空间。一个进程崩溃不会影响其他进程。

  

### 线程 Thread

CPU 程序执行 的最小单位。就像工厂里的工人，寄生于进程中。同一进程内的线程共享内存和资源，但一个线程崩溃通常会导致整个进程崩溃。

  

## 多进程 vs 多线程

### 多进程 Multiprocessing

内存占用高，切换开销大，数据共享困难，但安全性极强。最佳适用场景为 CPU密集型 任务，如科学计算、视频编码。

  

## 多线程 Multithreading

内存占用低，切换开销小，数据共享极易，但需要处理竞态条件。最佳适用场景为 I/O密集型 任务，如网络爬虫、文件读写。


## 适用场景
### 多进程
	主要适合大数据处理，低频交互，任务相互独立的场景，比如Web服务器的独立子进程处理请求
## 多线程
	适合高频计算，I/O密集型任务，如文件操作，网络请求，实时数据处理等
## Python 特殊情况

受限于 GIL，Python的多线程在CPU密集型任务中表现不佳。Python处理CPU密集任务必须使用多进程，而I/O密集型任务首选多线程。至于这两种任务的区别详情[IO密集型和CPU密集型](/knowledge-base/knowledge/Python/IO密集型和CPU密集型.md)。
