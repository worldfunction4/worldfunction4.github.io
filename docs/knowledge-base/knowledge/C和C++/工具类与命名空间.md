# 关于工具类

<!-- more -->

相关：[单例模式](面向对象/设计模式/单例模式.md)、[命名空间](命名空间.md)、[inline与static](inline与static.md)
上面关于`inline`和`static`又牵扯到工具类，这里也进行一个记录：
- 工具类其实算是一些工具函数的集合
- 它不扮演程序中的对象角色（比如`Person`， `Book`），因为它没有自己的数据和状态，仅仅是**行为/操作**的集合
可以用`namespace`代替`class`：
```cpp
class FileHelper {
private:
    FileHelper() = delete; //得手动禁用构造函数防实例化

public:
    static QString readAllText(const QString& path); // 2. 每个函数都要写 static
    static bool writeText(const QString& path, const QString& content);
    static bool copyFile(const QString& src, const QString& dest);
};
```
换成`namespace`：
```cpp
namespace FileHelper {
    // 天然无法被实例化（无需删构造函数）
    // 函数前面完全不用重复写 static
    QString readAllText(const QString& path);
    bool writeText(const QString& path, const QString& content);
    bool copyFile(const QString& src, const QString& dest);
}
```

## 这样看`static`的不可替代性变小了，那还有什么不可替代的场景呢？

### 单例模式
利用 C++11 保证的静态局部变量线程安全特性，写单例极其优雅：
```cpp
class ConfigManager {
public:
    static ConfigManager& instance() {
        static ConfigManager mgr; // 保证全局只有这唯一一个实例，且懒加载、线程安全
        return mgr;
    }
};
```

### 类的共享成员状态
当某个变量**必须属于类本身**，且需要被**类的所有对象共享**时：
```cpp
class Monster {
public:
    Monster() { totalCount++; }
    ~Monster() { totalCount--; }

    static int getTotalCount() { return totalCount; } // 获取当前活着的怪物总数

private:
    static inline int totalCount = 0; // 所有怪物对象共享这一个计数器
};
```
