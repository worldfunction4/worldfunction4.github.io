# 移动语义

## 背景

为了搞懂工作原理，先查看一个场景：
```cpp
class BigMemory {
    int* data; // 指向一块很大的堆内存
public:
    // ...
};

BigMemory getTempMemory() {
    BigMemory temp;
    // ... 在 temp 中分配并填充了 1GB 的数据 ...
    return temp;
}

BigMemory obj = getTempMemory(); // 用返回的临时右值初始化 obj
```

我们知道 `getTempMemory()` 返回的是一个**临时右值对象**，它在赋值结束后就会被销毁，那么传统的C++98拷贝构造函数是如何处理的？
根据拷贝构造函数做的事情：**必须重新开辟一块新的 1GB 内存，把数据完整复制一遍，然后再把临时对象销毁。这白白浪费了重新分配和复制 1GB 内存的巨额 CPU 与内存开销。**

所以为了提高效率以及减少内存开销，C++11中引入了**移动语义**： 既然临时对象马上要销毁，我们直接把它的指针“偷”过来（让新对象的 `data` 指针直接指向那块现成的 1GB 内存），然后把临时对象的指针置为 `nullptr`。只需复制一个 8 字节的指针，瞬间就完成了。


这个时候`std::move`就登场了。

## `std::move`

它的底层非常简单：比如说在`std::move(x)`中，**它自己不移动任何数据，只是做了一次强制类型转换**，把一个左值无条件转换为右值引用（`Type&&`）。这相当于给 `x` 贴上了一个标签：“**我不用它了，它的资源可以被安全‘窃取’了**”

> 需要注意的是：`x` 作为一个局部变量，在当前作用域结束之前，它在栈上的**内存依然存在**。状态是“有效但未指定”（Valid but unspecified），也就是说：**可以给它重新赋值，也可以安全地执行它的析构函数**（这就是为什么移动构造函数里必须把原对象的指针设为 `nullptr`，防止析构时重复释放）。


### NRVO(具名返回值优化)

有这么一段代码：
```cpp
Widget makeWidget() {
    Widget w;
    // ... 填充数据 ...
    return std::move(w); // 很多人以为这里写 std::move 能加速
}
```

编译器本身有一个叫 **NRVO（具名返回值优化）** 的“优化”：它能直接把 `w` 构造在调用者指定的内存里，达到**零拷贝、零移动**的最高效率。这里需要先介绍一下它的原理：

当写 `return w;` 时，编译器在编译期就会把 `w` 的内存地址，直接**重定向**到函数外部用来接收返回值的那个对象的内存空间里。

> 也就是说，`w` 和外部接收变量在内存里**本质上就是同一个东西**，既不需要拷贝，也不需要移动。


知道这一点后再来看上面的代码就会发现，当显式加上 `std::move(w)` 时：
	`std::move(w)` 产生了一个**右值引用** `Widget&&`。
	`return` 语句返回的不再是“局部变量本身”，而变成了一个“表达式”。
	编译器无法再做内存重叠（NRVO），只能老老实实调用一次**移动构造函数** `Widget(Widget&&)`，用这个引用去构造返回值。
这样原本的零开销也强行产生了一次开销了...

不过其实 C++11 标准也早已规定：当直接 `return w;` 时，**即使 NRVO 优化没有触发**，编译器也会**自动**优先尝试将 `w` 隐式当做右值进行移动，所以直接返回局部变量就是最好的。
