# 头文件防重复包含（Include Guard）

##  核心概念
在 C/C++ 中，当同一个 `.h` 头文件被同一个 `.cpp` 源文件直接或间接 `#include` 多次时，预处理器会多次展开该头文件，导致 **类/结构体/变量的重定义错误（Redefinition Error）**。

为了避免这个问题，需要使用 **防重复包含机制**。

---

##  传统做法：`#ifndef` 方式（ISO 标准）

### 代码结构
以 `MainWindow.h` 为例：

```cpp
#ifndef MAINWINDOW_H
#define MAINWINDOW_H

// 头文件主体内容
class MainWindow {
public:
    MainWindow();
};

#endif // MAINWINDOW_H
```
其中：
`#ifndef MAINWINDOW_H`：检查宏 `MAINWINDOW_H` 是否**未被定义**
如果未定义，则向下执行；如果已定义，直接跳转到 `#endif`，跳过中间所有代码
`#define MAINWINDOW_H`：立即定义该宏，立下“已被包含”的标记
`#endif`：标识防护作用域的结束。

> 命名规范 宏名称必须保证**全局唯一**。通常采用 `文件名_H` 的大写形式，例如 `mainwindow.h` $\rightarrow$ `MAINWINDOW_H`。

##  现代做法：`#pragma once` 方式
在头文件顶部添加一行即可：
```cpp
#pragma once

class MainWindow {
public:
    MainWindow();
};
```

意思是：直接告知编译器该物理文件在同一个编译单元中只会被包含一次，由编译器本身维护文件读取状态


## 两种方式的对比

| **维度**    | **#ifndef 方式**              | **#pragma once 方式**              |
| --------- | --------------------------- | -------------------------------- |
| **标准兼容性** | **ISO C/C++ 官方标准**，100% 跨平台 | 非标准扩展（主流编译器如 GCC/Clang/MSVC 均支持） |
| **判定依据**  | 宏名称（Macro Name）             | 物理文件路径（File Path）                |
| **书写难度**  | 需要 3 行代码，且需维护唯一的宏名          | 只需 1 行代码，无需维护宏名                  |
| **潜在风险**  | 跨文件宏名重名可能导致文件被意外跳过          | 在复杂软链接、网络文件系统下可能判定文件失误           |

## 关于使用方面的建议

- **Qt / 大型开源项目**：倾向于使用 `#ifndef`（例如 Qt Creator 自动生成的工程代码），以保证最高级别的跨平台兼容性。
    
- **现代商业项目 / 个人项目**：大部分使用 `#pragma once`，简洁高效，降低维护成本。

## 关于`#pragma once`和`inline`的误解
学习时不小心把两者混合误解了
- **`#ifndef` / `#pragma once`** 解决的是：防止同一个 `.h` 文件在 **【同一个 `.cpp` 文件】** 中被重复 `#include`（编译阶段
- **`inline`** 解决的是：允许多个 **【不同的 `.cpp` 文件】** 同时 `#include` 这个 `.h` 文件（链接阶段）

### 例子
举个例子：如果有两个源文件`main.cpp`和`db.cpp`，两者都`#include "config.h"`，那么两者在这其中的作用是什么呢？

- `#pragma once`：在编译 `main.cpp` 时，如果它因为嵌套关系包含了两次 `config.h`，`#pragma once` 会阻止第二次包含，保证 `main.cpp` 里面只出现一份代码

- `inline`：编译器在处理完后，会把 `main.cpp` 编译成 `main.o`，把 `db.cpp` 编译成 `db.o`， 这时，`main.o` 里有一份 `WORK` 变量，`db.o` 里也有一份 `WORK` 变量，最后把这两个 `.o` 连在一起（链接阶段）时，会因为有两个`WORK`然后报错：`linker error: duplicate symbol / multiple definition`，加入`inline`告诉编译器这两个`WORK`其实是同一个东西，合并为一份处理即可。
