# RAII

## 定义

**资源获取即初始化**：在构造函数里拿到资源，在析构函数里释放。对象活着资源就在，对象销毁资源一定还回去。

C++ 里异常、提前 `return` 都很常见，靠人手写 `unlock()` / `delete` 很容易漏。把资源绑在对象寿命上，离开作用域就会跑析构，漏不掉。

已经在用的两处：

<!-- more -->

- `std::lock_guard`：构造上锁，析构解锁。见 [互斥锁](C++11现代特性/互斥锁.md)
- `std::unique_ptr`：构造接管堆内存，析构 `delete`。见 [智能指针](C++11现代特性/智能指针.md)

```cpp
#include <mutex>
#include <memory>

std::mutex mtx;

void f() {
    std::lock_guard<std::mutex> lock(mtx); // 进门拿钥匙
    auto p = std::make_unique<int>(1);     // 进门拿到堆内存
    if (出错) return; // 仍然安全：lock 和 p 析构，锁会开、内存会还
} // 到这里一样会析构
```

自己写类也可以：构造里 `new` / `fopen` / 拿锁，析构里对应释放，并且把拷贝关掉（或认真实现），避免两份对象释放同一块资源。

## 示例

假设在执行代码的过程中，**程序中间突然发生了报错/抛出了异常（Exception）**，导致函数被强行提前中断退出：

- 场景 A：使用传统的 `new` 和 `delete` 手动管理。
    
- 场景 B：使用基于 RAII 的智能指针管理。
分别会发生什么情况？

A：由于中间突然报错抛出异常，下面的代码不会继续被执行，所以delete释放代码也不会执行，会导致通过new在堆上的内存无法被释放，造成内存泄漏。

B:抛出异常时，C++ 会触发[栈展开](../专业术语/栈展开.md) 。由于智能指针对象**本身保存在栈上** ，栈展开保证了它的析构函数一定会执行，从而彻底避免了堆内存泄漏。
