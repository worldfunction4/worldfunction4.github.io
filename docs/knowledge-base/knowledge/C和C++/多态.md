## 动态多态的底层原理

### 先看一段代码

```cpp
class Animal {
public:
    virtual void speak() { cout << "动物叫"; }
};

class Dog : public Animal {
public:
    void speak() override { cout << "汪汪"; }
};

class Cat : public Animal {
public:
    void speak() override { cout << "喵喵"; }
};

void doSpeak(Animal& animal) {
    animal.speak();  // 这里怎么知道调哪个？
}

Dog dog;
Cat cat;
doSpeak(dog);  // 输出：汪汪
doSpeak(cat);  // 输出：喵喵
```

**问题**：`doSpeak` 的参数是 `Animal&`，但传入 Dog 就调 Dog 的 speak，传入 Cat 就调 Cat 的 speak。**编译时根本不知道传入的是谁，运行时才知道——这是怎么做到的？**

---

### 核心机制：虚函数表（vtable）和虚函数指针（vptr）

C++ 的动态多态靠的是**两张表 + 一个指针**：

```
对象内存布局（以 Dog 为例）：

┌──────────────────┐
│  vptr  ──────┐   │     ┌──────────────────────┐
│  (指针)      │   │     │ Dog 类的虚函数表      │
│              │   └─────│──────────────────────│
│ 成员变量...  │         │ &Dog::speak  (地址)   │
└──────────────────┘     └──────────────────────┘
                             ↑ 指向 Dog::speak() 的代码
```

**关键两点**：

1. **vptr（虚函数指针）**：每个**有虚函数的对象**内部都隐藏着一个指针，指向该类的虚函数表
2. **vtable（虚函数表）**：每个**有虚函数的类**都有一张表，表中存储了该类的虚函数地址

---

### 一步一步拆解：对象创建时发生了什么

#### 第一步：编译阶段，编译器为每个类生成虚函数表

```cpp
// Animal 类的虚函数表（编译器生成，存在代码区）
Animal::vtable = [ &Animal::speak ]

// Dog 类的虚函数表（Dog 重写了 speak）
Dog::vtable = [ &Dog::speak ]

// Cat 类的虚函数表（Cat 重写了 speak）
Cat::vtable = [ &Cat::speak ]
```

#### 第二步：对象创建时，vptr 指向对应类的虚函数表

```cpp
Animal animal;  // animal 的 vptr → Animal::vtable
Dog dog;        // dog 的 vptr → Dog::vtable
Cat cat;        // cat 的 vptr → Cat::vtable
```

#### 第三步：调用虚函数时，通过 vptr 找到正确的函数

```cpp
void doSpeak(Animal& animal) {
    animal.speak();
    // 实际执行的是：
    // 1. 找到 animal 对象的 vptr
    // 2. 通过 vptr 找到 vtable
    // 3. 从 vtable 中取出 speak 函数地址
    // 4. 调用该地址对应的函数
}
```

```
doSpeak(dog) 时：

    dog 对象
    ┌────────────┐
    │ vptr ──────┼──→ Dog::vtable ──→ Dog::speak()  ← "汪汪"
    └────────────┘

doSpeak(cat) 时：

    cat 对象
    ┌────────────┐
    │ vptr ──────┼──→ Cat::vtable ──→ Cat::speak()  ← "喵喵"
    └────────────┘
```

### 为什么叫"动态多态"？

| 对比 | 静态多态（函数重载） | 动态多态（虚函数） |
|------|-------------------|------------------|
| **地址确定时机** | 编译阶段 | 运行阶段 |
| **调用方式** | 编译时直接定好地址 | 运行时通过 vptr 查表 |
| **速度** | 快（直接调用） | 略慢（多一次查表） |
| **灵活性** | 编译时确定，无法改变 | 运行时动态决定 |

### 虚函数表的"覆盖"机制

```cpp
class Animal {
public:
    virtual void speak() { cout << "动物叫"; }
    virtual void eat()   { cout << "吃东西"; }
};

class Dog : public Animal {
public:
    void speak() override { cout << "汪汪"; }  // 重写 speak
    // 没有重写 eat
};
```

Dog 的虚函数表是什么样的？

```
Animal::vtable          Dog::vtable
┌──────────────┐       ┌──────────────┐
│ &Animal::speak │       │ &Dog::speak   │  ← 覆盖：指向 Dog 自己的版本
│ &Animal::eat   │       │ &Animal::eat  │  ← 没重写，还是指向父类的
└──────────────┘       └──────────────┘
```

**规则**：
- 子类**重写**了哪个虚函数，表中对应的位置就**替换**成子类的函数地址
- 子类**没重写**的，表中保留父类的函数地址

### 用 sizeof 验证 vptr 的存在

```cpp
class NoVirtual {
    int a;
};

class HasVirtual {
    int a;
public:
    virtual void func() {}
};

cout << sizeof(NoVirtual);   // 4（只有 int）
cout << sizeof(HasVirtual);  // 16 或 12（int + vptr，还有内存对齐）
```

多出来的字节就是**vptr（虚函数指针）**，64 位系统上占 8 字节。

---

### 总结

```
动态多态底层 = vptr（对象里的隐藏指针） + vtable（类的虚函数表）

调用流程：
对象.virtual_func()
    ↓
通过对象的 vptr 找到所属类的 vtable
    ↓
从 vtable 中取出 virtual_func 的地址
    ↓
调用该地址指向的函数
    ↓
不同对象→不同 vptr→不同 vtable→不同函数地址→不同行为 ✅
```


## 纯虚函数

语法： `virtual 返回值类型 函数名 （参数列表） = 0`

**一个类中如果出现了纯虚函数，那么这个类就是一个抽象类**
抽象类的特点：无法实例化对象。抽象类的子类必须要重写父类的纯虚函数。




## 虚析构和纯虚析构

可以解决父类指针释放子类对象的问题（父类指针在释放时只会释放本身）
和纯虚函数一样，如果类中有纯虚析构那么这个类也被称作抽象类。
两者都需要有具体的函数实现
