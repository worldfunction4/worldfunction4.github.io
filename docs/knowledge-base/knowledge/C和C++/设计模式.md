众所周知C++也有着不同的设计模式供我们进行使用和参考，所以我开始进行学习：

# 工厂方法模式

学习工厂方法模式采用的是形状来进行练习（比如圆形，矩形，三角形等）。

### 核心设计思想

- **学习目标**：掌握工厂方法模式（Factory Method Pattern），实现系统对扩展开放、对修改封闭（**开闭原则 OCP**）。
    
- **核心结构**：双重继承体系
    
    -  **产品体系**：抽象基类 `Shape` $\rightarrow$ 具体产品 `Circle`, `Rectangle`, `Triangle`
        
    -  **工厂体系**：抽象工厂 `ShapeFactory` $\rightarrow$ 具体工厂 `CircleFactory`, `RectangleFactory`, `TriangleFactory`
        
- **内存管理**：使用 `std::unique_ptr` 自动管理对象生命周期，保证指针安全 。

### 思考与认知演进

#### 从“简单工厂”升级到“工厂方法”

- **旧认知**：简单工厂只需要一个工厂类，用 `switch/if-else` 创建对象。
    
- **发现问题**：每次增加新产品（如新怪物/新图形），都必须修改工厂类的源代码，违反了开闭原则。
    
- **突破**：将工厂也进行抽象，让每个具体产品对应一个具体工厂。扩展新产品时，只需要**新增代码**，无需**修改旧代码**。


#### 套用模板与质疑

- **真实感受**：“感觉写出来的代码像是背下来的公式/套模板，没有真正变成工程直觉。”
    
- **验证突破**：在不修改 `renderShape` 函数的前提下，独立扩写了 `Triangle` 和 `TriangleFactory`，体会到了“对扩展开放”带来的解耦优势。

## 疑难点与解决方案

#### 疑难点 1：多态调用机制（向上转型 Upcasting）

我的疑问是：**`void createAndattack(CreateMonster& fact)` 要求的参数类型是基类 `CreateMonster`，为什么把派生类对象 `CreatePig` 传进去可以正常运行？**

解答：

- **IS-A 关系**：派生类继承基类（`class CreatePig : public CreateMonster`），说明“野猪工厂**是一种**怪物工厂”。
    
- **向上转型**：C++ 编译器允许将派生类引用绑定到基类引用上。
    
- **虚函数表（vtable）**：当通过基类引用调用虚函数 `createmonster()` 时，C++ 会沿着虚函数表准确找到派生类 `CreatePig` 实现的版本。


#### 疑难点 2：无参工厂接口与带参产品构造的冲突

我的疑问是：**抽象工厂接口是统一且无参的（`virtual std::unique_ptr<Shape> createShape() = 0;`）。如果具体图形（如 `Circle` 需要半径，`Rectangle` 需要长宽）构造时需要参数，该怎么传？为什么工厂和产品类都需要保存参数？**

解答：

- **参数预存机制**：将参数的确定**提前到工厂创建阶段**，而不是在生产图形时传参。
    
- **数据流向分析**：
    
    1. 实例化工厂 ：`CircleFactory c(1.0);` $\rightarrow$ 将参数 `1.0` 保存到工厂对象的 `radius_` 成员变量中。
        
    2. 业务函数调用 ：`renderShape(c)` 调用 `factory.createShape()`。
        
    3. 内部转接 ：工厂在 `createShape()` 内部执行 `return std::make_unique<Circle>(radius_);`，将暂存的参数传递给 `Circle` 的构造函数。
        
    4. 对象生成 ：`Circle` 收到参数并保存，供 `draw()` 绘制时使用。

### 最终完整代码实现

```cpp
#include <iostream>
#include <memory>

// ================= 1. 产品层 =================
class Shape {
public:
    virtual void draw() = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
public:
    Circle(double r) : radius_(r) {}
    void draw() override {
        std::cout << "绘制半径为 " << radius_ << " 的圆形\n";
    }
private:
    double radius_;
};

class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : width_(w), height_(h) {}
    void draw() override {
        std::cout << "绘制一个边为 " << width_ << "，高为 " << height_ << " 的矩形\n";
    }
private:
    double width_;
    double height_;
};

class Triangle : public Shape {
public:
    void draw() override {
        std::cout << "绘制三角形\n";
    }
};

// ================= 2. 工厂层 =================
class ShapeFactory {
public:
    virtual std::unique_ptr<Shape> createShape() = 0;
    virtual ~ShapeFactory() = default;
};

class CircleFactory : public ShapeFactory {
public:
    CircleFactory(double r) : radius_(r) {}
    std::unique_ptr<Shape> createShape() override {
        return std::make_unique<Circle>(radius_);
    }
private:
    double radius_;
};

class RectangleFactory : public ShapeFactory {
public:
    RectangleFactory(double w, double h) : width_(w), height_(h) {}
    std::unique_ptr<Shape> createShape() override {
        return std::make_unique<Rectangle>(width_, height_);
    }
private:
    double width_;
    double height_;
};

class TriangleFactory : public ShapeFactory {
public:
    std::unique_ptr<Shape> createShape() override {
        return std::make_unique<Triangle>();
    }
};

// ================= 3. 业务逻辑层 =================
void renderShape(ShapeFactory &factory) {
    auto f = factory.createShape();
    f->draw();
}

// ================= 4. 主函数测试 =================
int main() {
    CircleFactory c(1.0);
    RectangleFactory r(3.5, 4.6);
    TriangleFactory t;

    renderShape(c);
    renderShape(r);
    renderShape(t);

    return 0;
}
```

当然也总结了一下优缺点：

**优点** :1. 彻底解耦产品创建与使用。
	2. 严格遵循开闭原则，扩展新产品无需修改旧代码。

**缺点**:类数量成倍增加（有 $N$ 个产品就需要配套 $N$ 个具体工厂），增加了系统代码复杂度。|


## 进阶操作

实现一个可扩展、内存安全且支持批量渲染的矢量图形绘制系统，当然具体功能没有实现。

**三层架构**：

-  **产品层（Product）**：抽象基类 `Shape` $\rightarrow$ 具体产品 `Circle`, `Rectangle`, `Triangle`
    
-  **工厂层（Factory）**：抽象工厂 `ShapeFactory` $\rightarrow$ 具体工厂 `CircleFactory`, `RectangleFactory`, `TriangleFactory`
    
-  **批处理/业务层（Batch Processor）**：`Canvas` 画布类，负责管理图形生命周期与统一渲染。

### 阶段一：工厂方法模式（基类与参数解耦）

- **突破**：通过在**工厂对象**内部“预存/暂存”构造参数（如 `radius_`），既保证了抽象工厂 `createShape()` 统一的无参多态接口，又保留了动态创建带参产品的灵活性。

### 阶段二：从单次绘制到批处理系统（Canvas）

- **思考**：实际绘图软件需要保存并管理多个图形。
    
- **突破**：使用 `std::vector<std::unique_ptr<Shape>>` 作为存储容器：
    
    - **多态性** ：通过基类指针统一存储不同派生类对象。
        
    - **内存安全** ：`Canvas` 独占图形所有权，销毁时自动释放内存，绝无泄露。
        
    - **高效传递** ：利用 **移动语义 (`std::move`)**，在不发生任何内存拷贝的前提下将指针所有权转移给 `Canvas`。

### 核心疑难点与解析

#### 疑难点 1：为什么选用 `std::unique_ptr` 而不是 `std::shared_ptr`？

**解析**：

- **独占所有权**：在绘图系统中，`Canvas` 是图形唯一的管理者。`unique_ptr` 明确表达了这种“独占”关系，开销与裸指针完全一致（零额外开销）。
    
- **避免共享复杂性**：`shared_ptr` 需要维护引用计数，仅在多个对象需要共同拥有同一资源时才使用。

#### 疑难点 2：向 `std::vector<std::unique_ptr<Shape>>` 添加元素时如何正确转移所有权？

- **错误写法**：`auto shapes_ = std::move(shape);` （创建了局部变量，函数结束即销毁，未存入容器）。
    
- **正确写法**：`shapes_.emplace_back(std::move(shape));`
    
- **解析**：
    
    - `std::unique_ptr` 禁止拷贝，必须显式调用 `std::move()` 触发**移动构造函数**。
        
    - `emplace_back` 配合 `std::move` 可以直接在容器尾部就地生成元素，性能最高。

#### 疑难点 3：高性能容器预分配：`reserve()` VS `resize()`

- **`resize(n)`** ：改变 Size（实际元素数量），会真的往容器里填充 $n$ 个空指针（`nullptr`），导致后续 `emplace_back` 插入在第 $n+1$ 个位置。
    
- **`reserve(n)`** ：改变 Capacity（容量/预留空间），提前向系统申请足够内存，但保持 Size 为 0。在 `Canvas` 构造函数中使用 `reserve` 可以有效避免频繁插入时的**重新分配内存（Reallocation）**。

### 完整重构代码实现

```cpp
#include <iostream>
#include <memory>
#include <vector>

// ================= 1. 产品层 (Shape) =================
class Shape {
public:
    virtual void draw() = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
public:
    Circle(double r) : radius_(r) {}
    void draw() override {
        std::cout << "绘制半径为 " << radius_ << " 的圆形\n";
    }
private:
    double radius_;
};

class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : width_(w), height_(h) {}
    void draw() override {
        std::cout << "绘制一个宽为 " << width_ << "，高为 " << height_ << " 的矩形\n";
    }
private:
    double width_;
    double height_;
};

class Triangle : public Shape {
public:
    void draw() override {
        std::cout << "绘制三角形\n";
    }
};

// ================= 2. 工厂层 (Factory) =================
class ShapeFactory {
public:
    virtual std::unique_ptr<Shape> createShape() = 0;
    virtual ~ShapeFactory() = default;
};

class CircleFactory : public ShapeFactory {
public:
    CircleFactory(double r) : radius_(r) {}
    std::unique_ptr<Shape> createShape() override {
        return std::make_unique<Circle>(radius_);
    }
private:
    double radius_;
};

class RectangleFactory : public ShapeFactory {
public:
    RectangleFactory(double w, double h) : width_(w), height_(h) {}
    std::unique_ptr<Shape> createShape() override {
        return std::make_unique<Rectangle>(width_, height_);
    }
private:
    double width_;
    double height_;
};

class TriangleFactory : public ShapeFactory {
public:
    std::unique_ptr<Shape> createShape() override {
        return std::make_unique<Triangle>();
    }
};

// ================= 3. 画布管理层 (Canvas) =================
class Canvas {
public:
    // ⚙️ 构造函数：预分配 10 个元素的内存空间，提升性能
    Canvas(size_t initial_capacity = 10) {
        shapes_.reserve(initial_capacity);
    }

    // 📥 移动所有权并存入容器
    void addShape(std::unique_ptr<Shape> shape) {
        shapes_.emplace_back(std::move(shape));
    }

    // 🖌️ 批量多态绘制
    void drawAll() const {
        std::cout << "=== 开始画布批量绘制 (共 " << shapes_.size() << " 个图形) ===\n";
        for (const auto& shape : shapes_) {
            shape->draw();
        }
    }

private:
    std::vector<std::unique_ptr<Shape>> shapes_;
};

// ================= 4. 主函数测试 =================
int main() {
    // 实例化工厂
    CircleFactory c(5.0);
    RectangleFactory r(3.0, 4.0);
    TriangleFactory t;

    // 创建画布
    Canvas canvas;

    // 生产图形并移动入画布
    canvas.addShape(c.createShape());
    canvas.addShape(r.createShape());
    canvas.addShape(t.createShape());

    // 批量渲染
    canvas.drawAll();

    return 0;
}
```
