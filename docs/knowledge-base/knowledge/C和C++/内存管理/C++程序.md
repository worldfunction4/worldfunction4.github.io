# C++程序

一段程序从运行到销毁，这其中内存的管理主要是分为四个维度

## 内存布局

在一段c++程序中内存部分分为了以下几个部分：

### 栈区（Stack）

它主要存放的是**局部变量，函数参数，指针本身**，这部分使用系统自动进行管理，特点是速度极快，且空间较小。

### 堆区（Heap）

这部分主要存放由**new/malloc**动态开辟的数据，采用程序员手动申请与释放，特点是空间巨大，灵活，需要防止泄露。

### 全局/静态区

存放全局变量，`static` 静态变量，程序启动时进行分配，结束时就会销毁，特点为：生命周期贯穿整个程序运行。

### 代码与常量区

存放函数代码指令，字符串常量，采用操作系统管理，特点为只读，修改会触发崩溃。

### 例子

根据以上四个区域，如果有以下一行代码：
```cpp
const char* str = "Hello World";
```
这里需要拆分成**指针本身**和**指向的内容**两部分来看：
1.指针本身：由于是在函数内部定义的局部变量，所以依然保存在**栈区**。
2.字符串常量：保存在**代码与常量区**（也就是只读数据段.rodata）

如果试图执行以下的代码，会发生什么？
```cpp
char* p = "Hello World"; // 试图用普通指针指向常量
p[0] = 'h';              // 试图把 'H' 改成 'h'
```

这样程序就会出现问题并崩溃报错。涉及到两个层面的报错：
1.编译期：在现代c++中，编译器会直接报错或警告，因为禁止字符串常量转换为普通的`char*`，强制要求写为`const char*`
2.运行期：如果强制绕过警告直接执行，运行时会触发*段错误（Segmentation Fasult）* 或 *内存访问违规(Access Violation)* 并直接崩溃。因为os和CPU会对常量区进行只读保护，任何视图写入的操作都会被拦截。

## 内存开辟

在c/c++中向堆区申请内存的手段有：C语言的`malloc`以及C++的`new`。

### new和malloc的区别
<!-- more -->

除了写法不同，一个是函数，一个是运算符，详情可以见[new关键字](../new关键字.md)。这里主要说明一下两者的区别。

`malloc` 与 `new` 最本质的区别在于：**面向过程 vs 面向对象* ：

**`malloc` （纯粹分配内存）**：它只管向堆区要指定字节数的“原始内存”，返回 `void*` 指针。它完全不知道这块内存将来存什么，**绝不会去调用构造函数**。

**`new` （分配内存 + 构造对象）**：它做的是两个部分：

1. 调用 `operator new` 向堆区申请一块足够大的内存（底层通常使用 `malloc`）。
    
2. 自动调用对象的 **构造函数（Constructor）** 来初始化这块内存。

举个例子：
```cpp
class Person {
public:
    Person() { 
        std::cout << "Person 被创建了！" << std::endl; 
    }
};
```

**方式 A**：`Person* p1 = (Person*)malloc(sizeof(Person));`
**方式 B**：`Person* p2 = new Person();`

根据区别，只有B才会在控制台打印相应内容。

### 内存消耗以及额外开销
那么，如果申请4个字节的内存，那系统真的就只会消耗4个字节吗？
答案肯定是比4个字节多得多。因为：

1.**内存对齐 (Memory Alignment) ** CPU 每次从内存读取数据时，是以固定块（如 4 字节或 8 字节）为单位读取的。为了让 CPU 访问更快，编译器会在变量之间加入无意义的 **填充字节（Padding）**。

2.**堆块元数据开销 (Header / Metadata) **：当你用 `new` 或 `malloc` 申请内存时，内存分配器（如 `ptmalloc`）必须记录这块内存的大小、是否正在使用等信息。这些额外的信息通常会直接贴在分配给你的那块内存**最前面**（Header），占用额外的 8~16 字节。

先来看第一种，举个例子：
假设在 64 位系统下，我们定义了这样一个简单的结构体
```cpp
struct Student {
    char grade; // 1 字节
    int age;    // 4 字节
};
```

从直觉上看，`1 + 4 = 5` 字节，
但由于 **`int`（4 字节）要求它的起始地址必须是 4 的倍数**，编译器会在 `grade` 后面自动填充一些空隙。所以sizeof（）读出来实际上是8个字节。

再看看第二种：
如果在堆区申请内存：
```cpp
int* p = new int(10); // 申请一个 int (4 字节)
```
虽然只申请了 4 字节，但**操作系统实际为你划拨的堆内存远大于 4 字节**（往往在 16~32 字节左右）：

**数据区**：存储数值 `10`（4 字节 + 4 字节对齐 = 8 字节）

**元数据区 (Header)**：内存分配器在指针**正前方**默默贴了一块隐形标签（通常占 8 或 16 字节），用来记录这块内存的大小、前后内存块的地址以及使用状态。

这也就是为什么当我们执行 `delete p` 时，**不需要**告诉系统要释放多少字节，系统却能精准地知道要回收多大一块内存 —— 因为它会先去读取指针前面的 Header 标签

## 释放与回收

在 C++ 中，开辟与释放必须成对出现：
```cpp
Person* pArray = new Person[5]; // 在堆区开辟了包含 5 个对象的数组
delete pArray;                   // 错误地使用了 delete 而不是 delete[]
```
会发生什么？

1.**析构函数少调用**：`delete`认为指针指向单个对象，因此只会对`pArray[0]`调用1次析构函数，剩下4个对象的析构函数完全不会执行

2.**堆内存错位崩溃**： 当使用`new Person[5]`时，编译器会在数组最前面默默多开辟几个字节，专门用来存**数组长度**5（这被称为 Cookie）。普通的 `delete` 不知道这个偏移量的存在，去读取释放信息时就会 **指针错位**，直接触发未定义行为（Undefined Behavior）导致程序崩溃

所以现在其实更推荐现代化的解法：[智能指针](../C++11现代特性/智能指针.md)：
```cpp
// 现代 C++ 推荐写法：无需手动 delete，出了作用域自动清理
std::unique_ptr<Person[]> pArray = std::make_unique<Person[]>(5);
```
