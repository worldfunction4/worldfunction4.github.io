# C++ 迭代器失效规则（Iterator Invalidation）

> **信息来源**：基于 C++ 标准（C++11/14/17/20）及 cppreference.com 文档。
> **注意**：由于环境限制，无法直接访问网络，以下内容基于标准规范知识整理。

---

## 一、总体对比表

| 容器 | 插入操作 | 删除操作 | 重新分配（扩容） |
|------|----------|----------|------------------|
| `vector` | 插入点**之后**的迭代器/引用/指针失效 | 删除点**之后**的迭代器/引用/指针失效 | 触发扩容时**全部**失效 |
| `deque` | 中间插入：**全部**失效；首尾插入：**全部失效**（C++11起首尾插入不失效？详见下文） | 中间删除：**全部**失效；首尾删除：仅被删元素失效 | — |
| `list` | **不失效**（所有迭代器保持有效） | **仅被删除元素**的迭代器失效 | — |
| `forward_list` | **不失效** | **仅被删除元素**的迭代器失效 | — |
| `map` / `multimap` | **不失效** | **仅被删除元素**的迭代器失效 | — |
| `set` / `multiset` | **不失效** | **仅被删除元素**的迭代器失效 | — |
| `unordered_map` | **可能失效**（rehash 时全部失效） | **仅被删除元素**的迭代器失效 | — |

## 二、`std::vector` 详细规则

### 2.1 插入（insert / push_back / emplace / emplace_back）

- 如果插入导致 `size() > capacity()`（即触发重新分配内存）→ **所有迭代器、引用、指针全部失效**
- 如果没有触发重新分配 → 仅**插入位置之后**的迭代器/引用/指针失效（插入点之前的保持有效）

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};
auto it1 = v.begin();       // 指向 v[0]
auto it3 = v.begin() + 2;   // 指向 v[2] (值=3)

v.insert(v.begin() + 1, 99); // 在位置1插入99
// v = {1, 99, 2, 3, 4, 5}
// it1 仍有效（指向的还是 v[0]=1）
// it3 已失效！（指向的位置现在存储的是 3，但迭代器已无效）
```

### 2.2 删除（erase / pop_back / clear）

- `erase(pos)`：从 `pos` 开始到末尾的所有迭代器/引用/指针失效
- `erase(first, last)`：从 `first` 到末尾的所有迭代器/引用/指针失效
- `pop_back()`：仅被删除元素的迭代器失效；`end()` 迭代器也失效
- `clear()`：所有迭代器/引用/指针失效

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};
auto it = v.begin() + 2;    // 指向 3
v.erase(v.begin() + 1);     // 删除 2
// v = {1, 3, 4, 5}
// it 已失效！（元素被移动了）
```

### 2.3 正确删除元素的惯用法

```cpp
// ❌ 错误：删除后 it 失效，再 ++it 是未定义行为
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it % 2 == 0)
        v.erase(it);
}

// ✅ 正确：利用 erase 返回下一个有效迭代器
for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0)
        it = v.erase(it);
    else
        ++it;
}

// ✅ 更佳：erase-remove 惯用法
v.erase(std::remove_if(v.begin(), v.end(),
    [](int x) { return x % 2 == 0; }), v.end());

// ✅ C++20：erase_if
std::erase_if(v, [](int x) { return x % 2 == 0; });
```

### 2.4 扩容机制与迭代器失效

```cpp
std::vector<int> v;
v.reserve(100);  // 预分配容量，后续插入不会触发扩容

auto it = v.begin();
for (int i = 0; i < 50; ++i)
    v.push_back(i);  // 不扩容，迭代器保持有效
// it 仍然有效！
```

## 三、`std::deque` 详细规则

`deque` 的迭代器失效规则较为复杂，不同 C++ 版本有细微差异。

### 3.1 C++98/03 规则

| 操作 | 迭代器失效情况 |
|------|---------------|
| 在**中间**插入（insert） | **所有**迭代器失效（包括首尾） |
| 在**首部或尾部**插入（push_front/push_back） | **所有**迭代器失效 |
| 在**中间**删除（erase） | **所有**迭代器失效 |
| 在**首部或尾部**删除（pop_front/pop_back） | 仅被删除元素的迭代器失效 |

### 3.2 C++11 及之后规则

| 操作 | 迭代器失效情况 |
|------|---------------|
| 在**中间**插入（insert） | **所有**迭代器失效 |
| 在**首部或尾部**插入（push_front/push_back） | **所有**迭代器失效（C++11 起**引用和指针**不失效，但**迭代器**仍全部失效） |
| 在**首部或尾部**删除（pop_front/pop_back） | 仅被删除元素的迭代器失效，指向其他元素的引用和指针保持有效 |

> **注意**：C++11 起，deque 的首尾插入不使**引用和指针**失效（前提是不触发底层重新分配），但**迭代器**仍可能全部失效。deque 没有 capacity() 和 reserve()。

### 3.3 关键点

```cpp
std::deque<int> d = {1, 2, 3, 4, 5};
int& ref = d[0];       // 引用首元素
auto it = d.begin();   // 迭代器指向首元素

d.push_back(6);        // 尾部插入
// ref 可能有效（C++11 起引用可能有效）
// it  可能已失效（迭代器可能全部失效）
// ⚠️ 不要依赖此行为，插入后重新获取迭代器！
```

## 四、`std::list` 详细规则

`std::list` 是双向链表，迭代器失效规则最简单。

### 4.1 规则

- **插入**（insert / push_front / push_back）：**任何迭代器都不失效**
- **删除**（erase / pop_front / pop_back）：**仅被删除元素**的迭代器失效，其他迭代器保持有效
- **splice**（合并/转移）：迭代器不失效（被转移的元素迭代器仍有效，指向同一元素的新位置）
- **sort / remove / unique**：这些成员函数不使任何迭代器失效

```cpp
std::list<int> lst = {1, 2, 3, 4, 5};
auto it = lst.begin();   // 指向 1
auto it3 = std::next(lst.begin(), 2);  // 指向 3

lst.push_front(0);       // lst = {0, 1, 2, 3, 4, 5}
// it  仍有效（指向 1）
// it3 仍有效（指向 3）

lst.erase(it3);          // lst = {0, 1, 2, 4, 5}
// it3 已失效
// it  仍有效（指向 1）
```

### 4.2 链表的独特操作

```cpp
std::list<int> lst1 = {1, 2, 3};
std::list<int> lst2 = {4, 5, 6};
auto it = lst1.begin();       // 指向 1

lst1.splice(lst1.end(), lst2); // 将 lst2 移到 lst1 末尾
// lst1 = {1, 2, 3, 4, 5, 6}, lst2 为空
// it 仍然有效（指向 1）

// splice 后迭代器仍有效，指向原元素在新位置
```

## 五、`std::map` / `std::set` / `std::multimap` / `std::multiset` 详细规则

关联容器（基于红黑树）的规则与 list 类似。

### 5.1 规则

- **插入**（insert / emplace）：**任何迭代器都不失效**（指向其他元素的迭代器保持有效）
- **删除**（erase）：**仅被删除元素**的迭代器失效
- **clear**：所有迭代器失效

```cpp
std::map<int, std::string> m = {{1, "a"}, {2, "b"}, {3, "c"}};
auto it = m.find(1);   // 指向 {1, "a"}
auto it2 = m.find(2);  // 指向 {2, "b"}

m.insert({4, "d"});    // 插入新元素
// it  仍有效（指向 {1, "a"}）
// it2 仍有效（指向 {2, "b"}）

m.erase(it2);          // 删除 {2, "b"}
// it2 失效
// it  仍有效（指向 {1, "a"}）
```

### 5.2 遍历删除的正确方式

```cpp
// ✅ 正确：后置递增（it++ 返回原迭代器的副本，然后 it 前进）
for (auto it = m.begin(); it != m.end(); ) {
    if (it->second == "b")
        m.erase(it++);   // 先递增 it，再删除旧的 it
    else
        ++it;
}

// ✅ 也可以（C++11 起 erase 返回下一个迭代器）
for (auto it = m.begin(); it != m.end(); ) {
    if (it->second == "b")
        it = m.erase(it);
    else
        ++it;
}
```

### 5.3 `std::unordered_map` / `std::unordered_set`

- **插入**：如果触发 rehash（负载因子超出阈值），**所有**迭代器失效；否则不失效
- **删除**：仅被删除元素的迭代器失效

```cpp
std::unordered_map<int, std::string> um;
um.reserve(100);  // 预分配桶数，避免 rehash
auto it = um.begin();
// 只要不触发 rehash，插入不会使 it 失效
```

## 六、引用和指针的失效

> 迭代器失效的同时，对应的**引用**和**指针**也通常失效。

| 容器 | 引用/指针失效情况 |
|------|-------------------|
| `vector` | 与迭代器规则相同：扩容时全部失效；插入/删除点之后失效 |
| `deque` | 插入首尾时引用/指针不失效（C++11 起）；中间插入/删除时全部失效 |
| `list` | 插入不失效；删除仅被删元素失效 |
| `map`/`set` | 插入不失效；删除仅被删元素失效 |

## 七、C++ 标准（草案）原文引用

以下是 C++ 标准对迭代器失效的要求：

### vector ([vector.modifiers])

> Effects: ... Causes reallocation if the new size is greater than the old capacity. If no reallocation happens, all the iterators and references before the insertion point remain valid. — **插入点之前的迭代器和引用保持有效。**

> Effects: ... Invalidates iterators and references at or after the point of the erase. — **删除点及之后的迭代器和引用失效。**

### deque ([deque.modifiers])

> An insertion in the middle of the deque invalidates all the iterators and references to elements of the deque. An insertion at either end of the deque invalidates all the iterators to the deque, but has no effect on the validity of references to elements of the deque. — **中间插入使所有迭代器和引用失效；首尾插入使所有迭代器失效，但不影响指向元素的引用（C++11）。**

### list ([list.modifiers])

> Does not affect the validity of iterators and references. — **不影响迭代器和引用的有效性。**

### map ([map.modifiers])

> Does not affect the validity of iterators and references to elements. — **不影响指向元素的迭代器和引用的有效性。**

## 八、面试常见问题

### Q1: 为什么 vector 插入会使迭代器失效？
> 因为 vector 使用连续内存，插入新元素需要将插入点之后的元素**后移**，导致这些元素的内存位置改变。如果触发扩容，则所有元素会**搬迁到新内存**，所有迭代器都指向旧内存，全部失效。

### Q2: 为什么 list 插入不会使迭代器失效？
> list 是链表结构，每个元素独立分配在堆上。插入新元素只需修改**相邻节点的指针**，已有元素的内存地址不变，指向它们的迭代器自然保持有效。

### Q3: 如何在 vector 遍历时安全删除元素？
> 两种方式：(1) 用 `erase` 返回的迭代器；(2) erase-remove 惯用法；(3) C++20 的 `std::erase_if`。

### Q4: deque 的迭代器失效为什么比 vector 更复杂？
> deque 是**分段连续**结构（由多个固定大小的缓冲区组成），中间插入/删除可能导致缓冲区重新排列，所以全部失效。首尾操作只影响边界缓冲区，但迭代器内部可能包含 block 管理信息，所以首尾插入仍可能使迭代器失效（尽管引用不失效）。

## 九、快速记忆口诀

| 容器 | 插入失效 | 删除失效 |
|------|----------|----------|
| **vector** | 之后全失效，扩容全完蛋 | 之后全失效 |
| **deque** | 中间全失效，首尾迭代器也失效 | 中间全失效，首尾安全 |
| **list** | 永远安全 ✅ | 只删自己 |
| **map/set** | 永远安全 ✅ | 只删自己 |

> **一句话总结**：连续内存容器（vector、deque）插入/删除会导致后续迭代器失效；节点型容器（list、map、set）非常安全，只有被删除的元素迭代器失效。
