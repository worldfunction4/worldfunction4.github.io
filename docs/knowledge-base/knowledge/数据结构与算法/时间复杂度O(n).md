# 时间复杂度 (Time Complexity)

## 1. 什么是时间复杂度

时间复杂度不是算法的具体执行时间（秒），而是**描述随着输入规模增长，算法基本操作次数的增长趋势**。它帮助我们评估算法在大数据量下的表现，与机器性能无关。

## 2. 大 O 记法 (Big-O Notation)

- **O(表达式)** ：表示算法增长率的数量级。
    
- **核心规则**：
    
    1. 只保留增长最快的项（忽略低阶项）。
        
    2. 忽略常数系数。
        
- **示例**：若操作次数为 `3n² + 100n + 500`，时间复杂度为 **O(n²)**。
    

## 3. 如何分析时间复杂度

1. **找到最内层核心操作**：通常是循环体内的基本判断或赋值。
    
2. **计算该操作的执行次数**：与输入规模 `n` 的关系。
    
3. **用大 O 化简**：保留最高阶项。
    

**举例**：LeetCode 14 纵向扫描

python

for i in range(len(first)):      # 最多 M 次 (M = 第一个字符串长度)
    for s in strs[1:]:           # 最多 N-1 次 (N = 字符串数量)
        if ...: return ...

最坏情况（所有字符串相同）：总比较次数 ≈ M × (N-1) ≈ S（总字符数） → **O(S)**。

## 4. 常见时间复杂度及翻倍直觉

**翻倍实验**：当输入规模 `n` 变为 `2n` 时，操作次数的变化。

|复杂度|名称|n → 2n 时操作次数变化|常见算法举例|
|---|---|---|---|
|O(1)|常数|不变|数组索引访问|
|O(log n)|对数|增加一个常数|二分查找|
|O(n)|线性|翻 2 倍|线性遍历|
|O(n log n)|线性对数|翻 2 倍多一点（约 2.3 倍）|归并排序、快速排序（平均）|
|O(n²)|平方|翻 4 倍|冒泡排序、简单选择排序|
|O(2ⁿ)|指数|平方|穷举所有子集|

**直觉记忆**：

- **O(n)**：数据翻倍，工作量翻倍。
    
- **O(n²)**：数据翻倍，工作量变 4 倍（2²）。
    
- **O(log n)**：数据翻倍，工作量只加 1 次。
    
- **O(n log n)**：数据翻倍，工作量约 2 倍多一点（因为 `log(2n) = log n + 1`）。
    

## 5. 时间复杂度是否越低越好？

**通常情况下是，但需综合考量**：

1. **常数因子**：小规模数据时，O(n²) 可能因为常数小而快于 O(n log n)。
    
2. **空间复杂度**：时间复杂度低的算法可能占用大量内存（空间换时间）。
    
3. **实现复杂度**：开发时间、可维护性也是成本。数据量小时，简单粗暴的写法更有性价比。
    
4. **真实数据分布**：最好、最坏、平均情况可能不同（例如快速排序平均 O(n log n)，最坏 O(n²)）。
    

**结论**：追求更优的时间复杂度是优化方向，但实际工程中要权衡数据规模、内存限制和代码可读性。

## 6. 案例：LeetCode 14 各解法复杂度对比

（N：字符串个数，M：平均长度，S：总字符数 = N×M）

|解法|时间复杂度|核心原因|
|---|---|---|
|纵向扫描 / 横向扫描 / 分治|O(S)|每个字符最多被检查一次|
|二分查找法|O(S log M)|二分增加对数级判定次数|
|排序后比较首尾|O(S log N)|排序需要 O(N log N) 次字符串比较，每次 O(M)|
|暴力两两比较（不推荐）|O(N² M)|所有字符串对两两比较|

> **面试：纵向扫描 O(S)**，代码简单且线性最优。

## 7. 公式

- **对数换底**：`logₐ(n) = log_b(n) / log_b(a)`，因此大 O 中所有对数均等价，写作 **O(log n)**。
    
- **常见求和**：
    
    - `1 + 2 + ... + n = n(n+1)/2 ≈ n²/2` → O(n²)
        
    - `n + n/2 + n/4 + ... + 1 ≈ 2n` → O(n)（几何级数）
